# Failure taxonomy

Version 0.3.0 distinguishes three different failure sources instead of treating
every miss as a search failure.

## 1. Representation failure

The exact archive may not expose the relation required by a task. Current gaps
include:

- context-dependent multi-object roles
- graph matching across changing object sets
- nested containment and hole correspondence
- latent grouping that is not determined by color or connectivity
- variable separator and panel semantics

## 2. Grammar failure

No posterior can recover an absent executable program. Important missing
families include:

- conditional branches over object counts and relations
- recursive or iterative construction
- obstacle-aware path generation
- graph-to-graph object correspondence
- causal multi-stage transformations
- deeper typed composition with latent intermediate objects

## 3. Selection failure

Several programs may fit every demonstration exactly while producing different
test outputs. The Bayesian model addresses this with family reliability,
route-conditioned priors, atlas evidence, complexity, and posterior-diverse
attempts. Selection can still fail when the demonstrations do not distinguish
the competing abstractions.

Local residual lookup programs are a specific risk. They can interpolate the
few demonstrations while encoding a relation that is not stable on the test
input. They therefore receive separate learned priors, bounded mapping sizes,
and family-diverse portfolio caps.

## 4. Calibration failure

A candidate family can be rare enough that its posterior reliability is based
on little evidence. The release reports each Beta posterior concentration and
the Bayesian regression predictive variance. Low-support high means should not
be read as established family accuracy.

## 5. Runtime failure

Candidate generation still contains operators whose cost depends on object
count, grid area, or composition depth. The Kaggle runner applies a hard
per-task limit. The long-term correction is deterministic family budgets and
cached typed intermediate states, not simply a larger timeout.

## Priority order

1. Expand the typed relational object graph.
2. Add conditional and bounded iterative construction.
3. Replace local residual tables with interpretable residual operators.
4. Add counterfactual ambiguity tests.
5. Learn a training-only proposal router.
6. Audit every change on the fixed parameter split before another freeze.
