# Architecture

## 1. Scope

Version 0.3.0 implements a static ARC realization of the Projector-Resolved
Large Algebraic Signal Model. ARC-AGI-2 is not interactive, so the transition
graph and action planner from the broader PR-LASM architecture are intentionally
absent. The retained loop is:

```text
exact analysis
→ typed proposal portfolio
→ Bayesian program posterior
→ posterior predictive outputs
→ exact residual analysis
→ selective proposal refinement
```

Every operation is local, deterministic, NumPy based, and usable without an
internet connection or pretrained model.

## 2. Exact multi-atlas archive

Every demonstration grid is retained in several compatible coordinate systems.
The archive includes:

- spatial cell coordinates
- one projector per color
- unitary two-dimensional Fourier coefficients
- orthonormal Haar coefficients
- two, three, and four phase polyphase channels
- four-connected and eight-connected object packets
- attributed object graphs with area, bounding box, density, holes, symmetry,
  border contact, alignment, containment, and adjacency

The archive is not a concatenated image embedding. Each atlas has an explicit
analysis and reconstruction contract. Automated tests check numerical
reconstruction for every invertible atlas.

## 3. Nested signal states

The complete archive is preserved for exact verification. Fixed deterministic
projections produce three statistical views:

- **macro**, 48 coordinates
- **meso**, 96 coordinates
- **micro**, 192 coordinates

These states summarize global geometry, object relations, color structure,
frequency structure, wavelet energy, and polyphase organization. They are used
for inference only. They are never reported as exact reconstructions.

## 4. Typed proposal portfolio

Candidate programs are generated by four channels.

### Base program search

A bounded minimum-description-length search composes primitive geometry,
recoloring, cropping, scaling, movement, copying, symmetry, filling, and object
selection operations.

### Projector and structural programs

Direct inference proposes typed rules for gravity, panels, periodic structure,
polyphase completion, Kronecker expansion, object ranking, object attributes,
line construction, counts, frequency selection, and related exact operators.

### Residual refinement programs

A failed seed program may be refined through a deliberately restricted local
lookup grammar. Keys may use output color, input and output color, local object
context, or low-modulus polyphase address. Arbitrary coordinate memorization is
not permitted. A refinement enters the portfolio only when it reproduces every
demonstration exactly.

### Safe fallbacks

Identity, nonbackground crop, and simple output-shape baselines keep the
submission schema complete when no supported rule fits.

## 5. Task signal analysis

Demonstration differences are classified into a probability distribution over
routes:

```text
identity-like, recolor, geometry, crop/extract, expand, compress,
draw/add, erase/remove, translate, panel, periodic,
object-relational, mixed
```

The same analysis produces probabilities over coordinate atlases and over
macro, meso, and micro resolution. These distributions are evidence for the
program posterior rather than hard routing decisions.

## 6. Bayesian program posterior

For candidate program `g` and demonstrations `D`, the implementation forms a
finite posterior proportional to:

```text
demonstration likelihood
× family reliability
× route-conditioned family reliability
× atlas compatibility
× resolution compatibility
× Bayesian calibration reliability
× complexity prior
```

The demonstration term measures exact output agreement, shape agreement, cell
agreement, and residual energy in every atlas. Family and route reliability are
hierarchical Beta posteriors learned from public training tasks only. A
Bayesian ridge model estimates held-out candidate reliability from the task
state and candidate evidence. Its predictive variance is retained rather than
discarded.

The normalized posterior is represented at five levels:

- program
- program family
- coordinate atlas
- resolution
- predicted output

Posterior entropy and disagreement are written to optional diagnostics.

## 7. Posterior predictive attempts

Programs that produce the same test grid have their probability mass combined.
The two final attempts are selected from distinct posterior-supported
mechanisms when possible. A deterministic MDL expert remains available as an
audited portfolio component and regression guard. It is not confused with the
Bayesian posterior.

## 8. Exact verification and ambiguity

A candidate marked exact reproduces every demonstration output by array
equality, including dimensions. This is a sound execution claim, not a proof
that the candidate is the intended latent rule. Several exact programs can
agree on the demonstrations and disagree on the test input. The posterior and
two-attempt policy exist to represent that ambiguity explicitly.

## 9. Runtime isolation

The package CLI has a soft candidate-generation budget. The Kaggle runner gives
each task a separate subprocess and a hard wall-clock limit. BLAS thread counts
are fixed to one per worker. A timed-out worker receives a deterministic
identity and nonbackground-crop fallback. The complete output is schema checked
before it is written.

## 10. Reproducibility

The release records hashes for:

- the three runtime modules
- the fitted Bayesian calibration
- the hard-isolated runner
- the self-contained Kaggle notebook

The notebook verifies its embedded payload before execution. The package tests
verify that the installable and Kaggle runtime copies are byte-identical.
