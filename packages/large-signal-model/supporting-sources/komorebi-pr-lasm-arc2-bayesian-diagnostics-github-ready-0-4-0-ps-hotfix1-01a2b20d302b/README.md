# PR-LASM ARC2 Bayesian Entry

**Version 0.4.0 · Author: Komorebi P.**

PR-LASM ARC2 Bayesian Entry is an offline ARC-AGI-2 solver built as a finite
static realization of the Projector-Resolved Large Algebraic Signal Model. It
keeps exact multi-atlas grid records, constructs nested statistical states,
generates a typed portfolio of executable programs, and forms a calibrated
Bayesian posterior over programs, mechanisms, coordinate atlases, resolutions,
and predicted outputs.

The repository is Kaggle-ready and fully auditable. It is not presented as a
competitive ARC solver or as evidence of general intelligence.

## What changed in 0.4.0

Version 0.3.0 established the exact multi-atlas Bayesian Large Signal Model.
Version 0.4.0 strengthens its executable grammar and makes the residual audit a
first-class model component.

### Model expansion

The typed portfolio now includes generic exact-fit families for:

- marker-glyph-conditioned recoloring
- enclosed-region filling and attribute-conditioned region coloring
- periodic resizing with inferred color transfer
- Kronecker mask and complemented-motif variants
- modular affine index tiling
- object-chain packing
- object-shape and hole-conditioned recoloring
- periodic stripe construction from marker pairs

Every family is accepted only after exact execution against every demonstration.
No task IDs or expected test solutions are embedded in the solver.

Output posteriors now retain exact-fit support probability, exact-fit candidate
count, and best-candidate probability. Attempt selection prioritizes distinct
posterior-supported outputs generated by programs that fit all demonstrations
exactly before it uses approximate fallbacks.

### Diagnostic expansion

A local scored run can now produce a complete diagnostic atlas containing:

```text
all training demonstrations
held-out test input
expected solution
attempt 1 and attempt 2
mismatch-highlighted grids
residual category maps
cell agreement and wrong-cell counts
color-confusion tables
first mismatch coordinates
selected programs and posterior support
failure-stage diagnosis
```

The atlas is written as HTML, SVG, JSON, JSONL, and CSV. Exact ARC scoring is
unchanged. Partial agreement is diagnostic only.

See [the diagnostic atlas guide](docs/DIAGNOSTIC_ATLAS.md),
[the 0.4 model improvements](docs/MODEL_IMPROVEMENTS_0.4.0.md),
[the architecture](docs/ARCHITECTURE.md), and
[the Bayesian model specification](docs/BAYESIAN_LARGE_SIGNAL_MODEL.md).

## Measured status

The public training corpus was partitioned by the same deterministic task-ID
hash used in version 0.3.0. Parameters were fitted on 799 tasks. The remaining
201 tasks were excluded from parameter fitting and retained as a machine-level
parameter holdout.

| Audit | Result |
|---|---:|
| Synthetic regression outputs | 6/6 exact |
| Exact multi-atlas randomized reconstruction | maximum residual below `1.2e-14` |
| Calibration partition | 77/799 whole tasks, 86/857 outputs exact |
| Calibration output rate | 10.0350% |
| Locked parameter holdout | 30/201 whole tasks, 32/219 outputs exact |
| Locked parameter-holdout output rate | 14.6119% |
| Partition-combined public-training total | 107/1,000 whole tasks, 118/1,076 outputs exact |
| Partition-combined output rate | 10.9665% |
| Independent version 0.4.0 full-training rerun | **108/1,000 whole tasks, 119/1,076 outputs exact** |
| Historical version 0.3.0 full-training rerun | 89/1,000 whole tasks, 100/1,076 outputs exact |
| Historical version 0.3.0 holdout | 28/219 outputs exact |
| Version 0.4.0 public-evaluation score | Not run |
| Private competition score | Not available |

The parameter holdout is a machine-level holdout, not a claim of historical
novelty. Earlier project versions were already inspected on the complete public
training corpus.

### Bayesian selection result

On the fixed 201-task holdout and the identical candidate portfolio:

| Selector | Exact outputs |
|---|---:|
| Bayesian posterior | 32/219 |
| Deterministic ranker | 32/219 |
| Candidate-oracle union | 33/219 |

The Bayesian and deterministic selectors solve one different output each. The
Bayesian model therefore supplies calibrated probability, uncertainty, atlas
support, and mechanism attribution, but it does not yet improve aggregate exact
accuracy over deterministic ranking on the same 0.4 candidate set. The measured
holdout increase from 28 to 32 exact outputs is primarily attributable to the
expanded typed grammar and its recalibration.

## Exact multi-atlas analysis

For every grid, the solver retains:

```text
spatial
color projectors
unitary Fourier
orthonormal Haar
polyphase 2
polyphase 3
polyphase 4
object-relational graph
```

The exact archive and the statistical state are different objects. Statistical
compression is used to calibrate and route program hypotheses. Exact output
claims always come from executing a program and comparing the resulting grid by
array equality.

## Bayesian posterior

For candidate program `g` and demonstrations `D`, the finite posterior combines:

```text
demonstration likelihood
+ family reliability
+ route-conditioned reliability
+ atlas compatibility
+ resolution compatibility
+ Bayesian reliability prediction
+ complexity prior
```

Programs producing the same test grid have their posterior mass combined. The
model keeps posterior distributions over:

```text
program
family
atlas
resolution
output grid
```

Optional diagnostics expose top programs, probabilities, likelihood parts,
calibration mean and variance, entropy, disagreement, and output support.

## Install and verify

### Conda and PowerShell

```powershell
$Repo="$HOME\Downloads\komorebi-arc2-bayesian"; conda run -n komorebi-full python -m pip install --no-deps --no-build-isolation -e "$Repo"; if($LASTEXITCODE -eq 0){conda run -n komorebi-full python -m komorebi_arc2 --self-test}; if($LASTEXITCODE -eq 0){conda run -n komorebi-full python -m pytest "$Repo\tests" -q}
```

Equivalent repository wrapper:

```powershell
& .\powershell\Run_Bayesian_Self_Test.ps1 -Environment komorebi-full
```

The wrappers resolve a real Conda executable and work from `powershell.exe -NoProfile`. They check `CONDA_EXE`, `_CONDA_EXE`, the application path, and standard user-profile installations. An explicit path can be supplied when needed:

```powershell
& .\powershell\Run_Bayesian_Self_Test.ps1 -Environment komorebi-full -CondaExecutable "$HOME\miniconda3\Scripts\conda.exe"
```

Complete validation, including the randomized exact-atlas audit and an optional
official public-training subset:

```powershell
& .\powershell\Run_Full_Bayesian_Validation.ps1 -Environment komorebi-full -DataDir "$HOME\Downloads\ARC_AGI_2_OFFLINE_DATA" -TrainingTasks 25
```

## Run the official public training audit

```powershell
& "$Repo\powershell\Run_Diagnostic_Audit.ps1" -DataDir "$Data" -Environment komorebi-full -MaxTasks 1000 -DiagnosticLimit 100 -TimeLimit 0.05
```

This wrapper may also be launched from a clean child process:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$Repo\powershell\Run_Diagnostic_Audit.ps1" -DataDir "$Data" -Environment komorebi-full -MaxTasks 1000 -DiagnosticLimit 100 -TimeLimit 0.05
```

Use `-DiagnosticLimit 0` to render every scored output. The default keeps the browsable artifact compact while the JSON and CSV ledgers still report the selected run.

The installed package automatically loads its embedded calibration. Use
`--bayesian-calibration PATH` to audit a different calibration file.

## Refit the Bayesian model from public training data

```powershell
& .\powershell\Train_Bayesian_Calibration.ps1 -DataDir "$HOME\Downloads\ARC_AGI_2_OFFLINE_DATA" -Environment komorebi-full -TimeLimit 0.05 -MaximumCandidates 16
```

The training script has no argument for an evaluation or test solution file. It
accepts the public training challenge and solution files, creates the fixed
799/201 parameter split, fits the calibration, and writes both partition
results.

## Kaggle submission

Upload:

```text
kaggle/PR_LASM_ARC2_Kaggle_Entry.ipynb
```

Attach the ARC-AGI-2 competition data, keep internet disabled, and run all
cells. The notebook embeds and verifies:

```text
arc2_entry.py
atlas.py
lasm_bayesian.py
bayesian_lasm_calibration.json
run_submission.py
```

Expected outputs:

```text
/kaggle/working/submission.json
/kaggle/working/pr_lasm_arc2_runtime_report.json
```

The runner isolates every task in a subprocess. Default limits are an 8-second
soft candidate budget and a 20-second hard process limit. A failed task receives
a deterministic schema-valid fallback and is recorded in the runtime report.

## Claim boundary

Version 0.4.0 is a real finite Bayesian PR-LASM implementation for static ARC
tasks. It does not contain a neural foundation model, universal program
induction, persistent interactive memory, or a general planner. The principal
remaining limitation is the typed transformation grammar. Bayesian inference
can rank and quantify supported programs. It cannot recover a rule that no
candidate program can express.
