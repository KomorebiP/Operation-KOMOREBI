# Authoring corrections and diagnostic failures

This records transient authoring and inspection problems as well as mathematical corrections. Final verification applies to the corrected release, not to every intermediate draft.

1. An initial proposed figure theme incorrectly wrote `2 + 3^10 = 23^5`. The figure generator's exact assertion rejected it before publication. The correct benchmark is `2 + 109·3^10 = 23^5 = 6,436,343`, with radical `15,042`. A subsequent premature suggested factorization of `59,051` was also discarded. Exact checking confirms that number is prime. Neither incorrect suggestion is used as evidence in the readers.
2. A broad source search printed too much retrieved metadata and was truncated. Subsequent searches printed only bounded filename and identity summaries. Selected archive bytes, sizes, hashes, and CRC checks provide the actual recovery evidence.
3. One inspection script assumed every acquisition JSON file had a top-level array. A dictionary-shaped record triggered `AttributeError`. The corrected script checks the JSON shape. No source or mathematical computation was changed by this inspection failure.
4. The web preview of the raw LANA PDF returned an internal retrieval error. The official ZEN announcement was retrieved successfully, and the report PDF was separately downloaded, extracted, and hashed by the literature workflow. The preview failure is not a successful source check.
5. Preliminary reader builds, while new chapters and bibliography were still being written, had undefined citations. Final source and layout validation checks the completed bibliography and stabilized references.
6. After the final bibliography update, the build wrapper failed while decoding a TeX console byte `0xf6` as UTF-8. This was a console-decoding exception, rather than a failed mathematical proof. The wrapper now captures and stores console output as raw bytes and decodes only human-facing failure excerpts with replacement. The TeX sources remain UTF-8 and unchanged by this fix. Final compilation and reference stabilization were rerun.
7. The first final release-validator run assumed the figure reports used a `passed` status and a top-level list. The actual frozen reports use `bounded exact data verified` and a dictionary containing `all_passed` and `figures`. The assertion failed safely. The validator was corrected to consume that schema, verify the exact generator hash, and require all 24 canvas and card-bound checks. No figure, reader, or scientific data was changed.
8. Two cosmetic patch attempts did not match their proposed source contexts. They made no change. Reading the section headers identified the intended files, and the six successful opening-page-break removals were reviewed as formatting-only changes.

The independent proof audit records substantive inherited statement corrections, including the CRT nonempty-coordinate guard and exact theorem-domain qualifications. The computation and formal reports retain their own failed and corrected attempts. The formal report specifically records runtime extraction ownership errors, executable-path host compatibility, and dependency acquisition issues. The figure report records strict containment failures and corrected exports. These records should be read together with the final revision pins and passing checks.
