# Failures and corrections in this block

1. **Environment initialization.** The first development compiler call invoked `lake env` outside the restored kit's workspace. Lean could not find Mathlib. Supplying the documented workspace as the subprocess working directory fixed the search path. The missing-module diagnostic is retained in development/missing_workspace.log. No theorem was checked by the failed invocation.
2. **Lean expression formatting.** The point-map theorem initially tried to use a polynomial identity in an expanded form against field_simp's factored target. An explicit ring equality between those forms fixed the type mismatch. The mathematical statement did not change.
3. **Lean development linter failures.** The moduli module initially included an unused characteristic-zero instance on polynomial identities and redundant final tactics. The instance was restricted to the Fricke results where it is needed, and the unused tactics removed. No linter was disabled and no target weakened. The initial module is retained.
4. **Numerical implementation failure.** The first 40-digit run numerically differentiated an inherited lru-cached theta evaluator. A central theta value had been cached at the base precision, while mpmath requested higher-precision derivative samples. The resulting second derivative was spurious (normalized residual 1, scale about 10^72). The code was replaced by a direct termwise differentiated theta-product series; the original tolerance was retained. The failed source and diagnostic are retained. No mathematical conclusion was drawn from that failed run.

The final exact checker, numerical checks at both stated precisions, and all four Lean compilation stages pass. The fresh-extraction replay is recorded separately in REPLAY_RECEIPT.json; neither old development logs nor predecessor results count as new successful executions.

5. **Fresh-extraction replay tool limit.** A combined stages-1-and-2 invocation exceeded the outer tool time limit during the replay. No surviving Lean process remained. Stage 2 was rerun alone from the verified stage-1 source/hash boundary, followed by stages 3 and 4; all passed without changing source, timeout, or proof statements. The completed replay is the evidence used in REPLAY_RECEIPT.json.
