# Failures and corrections

1. A streaming container invocation was unsupported and failed before it created the restoration script. A follow-up path check therefore also failed. The script was then created and run synchronously. Runtime restoration completed and the archive SHA256 matched the prior pinned record.
2. A broad `public import Mathlib` smoke test reached the outer 180-second execution timeout under the 4-GiB environment. It is not counted as a passed check. Selective module imports replaced it; all final files compile with a single worker.
3. Development Lean drafts needed normal corrections: `ring` was unavailable under the narrow Ring.Basic import (replaced with `ring1`); a draft had theorem-body indentation at declaration level; several proof scripts retained tactics after the preceding tactic had already solved the goal; unused simp arguments and unnecessary sequence focus were removed under warnings-as-errors. The first Finsupp experiment also tested a nonexistent lemma name and omitted explicit homomorphism premises. These failed drafts were not accepted as proofs. Final files compile with no placeholders.
4. The first all-theorem audit parser recognized `depends on axioms: [...]` but not Lean's separate `does not depend on any axioms` output. Compilation itself had succeeded, but the runner correctly stopped at a coverage mismatch. The parser now recognizes both forms and still requires all 50 constants. The entire clean build was rerun.
5. A batched 50/90-digit numerical invocation exceeded its total 90-second container budget during the second precision. The 50-digit portion had completed; the interrupted 90-digit portion was not counted. Pure-function memoization was added, without reducing the domain or precision, and the final precisions were rerun separately and in the final pipeline.

There was no mathematical counterexample to the new norm classification. Negative controls deliberately distinguish norm-one functions from the constant one and the smoothing norm from unsmoothed dilation. The rejected Lean statement 0=1 is an expected negative control, not a failed theorem claimed as proved.

6. The single-call final pipeline was also interrupted by the tool execution envelope during its high-precision phase, although the standalone 90-digit run had succeeded. The unchanged test set is now run as two synchronous parts (`core` and `high`), each with separate source-integrity receipts. This does not remove tests or reduce precision.
