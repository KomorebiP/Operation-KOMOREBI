# Independent sealed-null semantic-retraction cross-check

Author: `Komorebi P.`  
Version: `0.2.0`  
Status: frozen and receipted; learned execution is unlocked only by the explicit flag

This directory contains a standalone, read-only NumPy sensitivity probe for
the twelve sealed v0.4 learned checkpoints. It deliberately does not import
PyTorch or the v0.4 source package. Checkpoints are decoded through a
restricted inert unpickler, hashes are checked before tensor use, and the
sealed `null` bank is regenerated byte for byte from its recorded seed.

The model path reconstructs the source formulas and operation order in NumPy
float32 where feasible. It is not a bitwise or `1e-6` equivalence claim for
the packaged PyTorch path: BLAS reductions and SVD can round differently, and
small differences can accumulate across a long rollout. Polar checkpoints
therefore also report raw-operator singular-value diagnostics. Any conclusion
from this cross-check is explicitly a NumPy-backend sensitivity and must be
qualitative and robust to that boundary.

The sensitivity panel starts all eight visible states in every one of the 64
sealed null contexts. It applies `r4`, `f2`, and `frfr` sixteen times, then
compares six endpoint interventions under all 31 binary suffixes of length at
most four. Every branch is matched against the clean learned anchor for the
same semantic state. The cross-fitted prototype excludes both the evaluation
context fold and the evaluated loop family.

The learned run is intentionally fail-closed. The protocol binds SHA-256
receipts for the executable and tests, and its final bytes are separately
receipted. The current receipts match; without those exact bytes and the
explicit `--run-learned` flag, the command refuses to touch checkpoint outcomes:

```bash
python probe_null_retraction.py --run-learned --root /path/to/Komorebi_Neuralese_Packet_Closure_v0.4.0 --archive /path/to/Komorebi_Neuralese_Packet_Closure_v0.4.0.zip --output RESULTS.json
```

Safe checkpoint-free validation is:

```bash
python probe_null_retraction.py --validate-only
python -m unittest -v test_null_retraction.py
```

These commands inspect only the local protocol and synthetic fixtures. They do
not load, encode, or evaluate a learned checkpoint.

Result creation is exclusive. An existing path, the source archive, and every
path inside the extracted v0.4 source tree are rejected rather than
overwritten.

The frozen work bound is 3,618,816 suffix endpoint evaluations and 4,497,408
batched 12 by 12 float32 matrix-vector transitions across all checkpoints.
The expected vectorized CPU runtime is roughly 20 to 45 seconds in this
environment and conservatively 30 to 90 seconds on a Windows laptop. This
estimate is anchored by 1.17-second warm and 2.53-second cold full synthetic
one-checkpoint replays. Peak
working memory is capped below 100 MB by processing one checkpoint at a time
and writing aggregate counts rather than per-sample logits.

This is a posthoc sensitivity analysis. Oracle and teacher-forced prototype
success show only that a tested semantic section is sufficient on this finite
panel. Self-decoded or nearest-anchor success is stronger but remains a
one-shot addressability result. None of these outcomes repairs the original
v0.4 result contract or proves an infinite, exact, or architecture-independent
quotient.
