# AVOC v0.24.0 — targeted gap update

Earlier theorem scopes remain unchanged. No broad-topic reset is implied.

## G28: durable paid component-promotion history
CLOSED FOR THE DECLARED PROTECTED FIXED-CATALOGUE PROTOCOL.
Prepayment, settled-gate equivalence, exact duplicate handling, abandonment,
canonical command replay, whole-campaign accounting and checkpoint restoration
are proved. The actual Lean gate drives a SQLite-backed component registry. The
registry retains rejected/abandoned reservations, commits promotion and dispatch
state together, and invokes the retained implementation after replay.

Still open: arbitrary verified source deployment, signed or rollback-resistant
history, universal host/serialization/SQL refinement, adaptive candidate catalogue,
multiwriter consensus and complete physical-cost accounting.

## G25: protected promotion
PRESERVED AND CONNECTED TO DURABLE JOURNALS.
The old contract and strict utility criterion are unchanged. Prepaid settlement
has exactly the inherited promotion result, not a new unverified score rule.

## G26: component optimization witness
PERSISTENT INVOCATION ADDED.
The existing threshold specialization is retained across process invocations.
This is not a new algorithm, measured physical speedup, or arbitrary code replacement.

## G27: recursive improvement of the improver
STILL OPEN.
No runtime LLM generates the candidate. No controlled experiment demonstrates an
accepted component producing better subsequent improvements than a frozen proposer.

## G16/G18: other execution and artifact interfaces
The new campaign registry is intentionally separate from older protected proof
stores. Arbitrary Lean/mathlib artifacts, dependency-bearing live research jobs,
general provenance replay and automatic integration with those stores remain open.

## G20/G21: actual costs and empirical benefit
All authorized evaluation/switch tariffs are retained. Replay and physical
computation costs remain outside those tariffs. No real LLM calibration,
productivity benchmark or globally optimal paid improvement search is established.

## Next concrete objective
Implement a costed candidate-generation/evaluation workload using a fixed protected
promotion objective. Compare frozen and upgraded proposers under matched full
resource budgets, or first add an independently checked arbitrary-Lean backend.
Do not confuse persistent deployment of a supplied candidate with autonomous
recursive improvement.
