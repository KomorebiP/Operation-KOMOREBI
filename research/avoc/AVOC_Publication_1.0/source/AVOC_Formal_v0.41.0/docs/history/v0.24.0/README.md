# AVOC v0.24.0 — prepaid durable component promotion

The fixed-authority v0.23 upgrade gate is now surrounded by a proved prepaid
journal and a protected local SQLite campaign. A new key reserves its evaluation
fee before the current candidate's gate evaluation. Finish uses the original
promotion criterion without charging that evaluation again. Abandonment retains
its charge and does not upgrade the active component. Exact repeated keys and
finished operations are idempotent at the ledger level.

The canonical event, materialized ledger and active compiled-component pointer
commit together. Every reopen replays the protected events through the actual
Lean gate and checks the stored checkpoint. Invocation then executes the retained
active implementation. The concrete catalogue remains dynamic, threshold and
always_retry. No arbitrary source code is installed or generated.

Start with FORMAL_THEORY.md, PROOF_BOUNDARY.md and REPRODUCE.md. The cumulative
source includes prior modules and evidence. Current proof and execution evidence
is under results/v0.24.0. Earlier evidence remains historical.

This release does not demonstrate autonomous recursive improvement. It makes one
checked component promotion persistent, auditable, and crash-testable, including
paid failed/abandoned trials. Host, SQLite, compiler/runtime and Python projection
remain trusted. Nominal tariffs do not measure every physical evaluation/replay cost.
