# AVOC v0.30.0 — failures, corrections and limits

## Proof-script corrections

1. The first `retarget_valid` proof used broad simplification around the lower-rank witness. Lean displayed apparently identical matrix types but did not accept that rewrite path. An explicit `change` and oriented rewrite fixed the proof. The offset and minimum-width claims were not weakened.
2. An unused field-instance warning failed the warnings-as-errors check. The theorem's unnecessary instance was explicitly omitted. A documentation comment placed before `omit` caused a subsequent parser error; the modifier/comment order was corrected.
3. The initial search-guard proof supplied an unused `Matrix.mul_apply` simplifier argument. Removing it satisfied the warning policy.
4. The codec's first proof carried an unused success premise because the returned checked object already included the relevant proof. Naming that argument as intentionally unused repaired the linter failure; the actual parsing/gate hypotheses remain explicit.

The successive `dev*_AffineReuse`, `dev*_AffineSearchGuard` and `dev*_AffineReuseCodec` logs are preserved. Final versions compile and appear in the complete axiom audit. There are no admitted placeholders or custom axioms in the positive source.

## Incomplete live-test batch

The first unsplit live cache regression was interrupted by the outer 90-second execution limit. It had printed partial progress but had not produced a complete final summary. It is **not counted as passing evidence**.

The script was split into independent `basic`, `economics`, and `integrity` groups. Each group creates its own fresh store and checked fixture. All 17 final cases passed against the finalized source. The differential regression was rerun after the test-script change so its source pins also match.

This was a host execution-limit interruption, not a mathematical counterexample or a claimed successful whole-suite run. No old live/crash-suite results were relabeled as new.

## Intended negative and adverse outcomes

The eleven-call cold example is an intentional adverse result: optimistic preflight permits exploration, but actual setup produces net -75. Passing the preflight test is only absence of that particular obstruction.

The ten-call warm example pays its revalidation and retargeting costs and has net +1 under declared tariffs. It does not establish general cache profitability.

A corrupted old affine offset is rejected even when a later requested offset could be generated by retargeting. The old certificate must first be valid.

The four new negative Lean files are intentionally invalid. Each reaches a substantive mathematical contradiction after valid imports. Their rejection complements positive obstruction theorems, not replaces them.

## Scope not silently closed

The Python proposer, tariff meter, config/store parser, serialization, OS and protected-host behavior are not universally formally verified. The live publication failure fixture is a controlled exception, not an application-kill or power-loss test. Persistent payment/recovery semantics are not imported into this new snapshot cache.

Preflight and cache tariffs are not all physical costs. Setup floors apply to the declared implementation route, not to every conceivable factorization algorithm. Minimum rank is not a minimum sparse or multistage arithmetic circuit theorem.

The final local build uses pinned external binary caches. No fresh mathlib-source build or independent runtime/kernel validation is claimed.
