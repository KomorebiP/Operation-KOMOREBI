# Review and corrections

A useful report identifies the claim ID or source declaration, the affected candidate version, the exact hypotheses or input, and the expected and observed conclusions. A mathematical objection should isolate the implication at issue. A software report should include the command, toolchain, exit status, and smallest available reproducer.

A failed demonstration, an unavailable dependency, a proof-build error, and a false theorem are different findings. They are recorded separately. A timeout is inconclusive, and an unexpected nonzero exit is not automatically a successful negative control.

Corrections preserve the affected release and state what changed. A change to a public theorem or its hypotheses requires updating the claim register and proof boundary. Changes to performance or reference code do not silently change mathematical scope.

Independent reproduction and review are welcome. The current evidence does not imply independent human review or an independently implemented proof kernel. Contribution and distribution terms have not yet been approved for this candidate; do not infer a new license from this document.
