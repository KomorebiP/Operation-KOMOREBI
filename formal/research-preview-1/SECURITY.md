# Sensitive reports and repository safety

Do not put access tokens, personal identifying information, private research
archives, or full environment dumps in public issues. Mathematical corrections
belong in the mathematical-correction template with the smallest relevant example.

For an actual security or privacy issue, use GitHub's private vulnerability-reporting
route only after the maintainer has enabled it. Until a private route is available,
withhold sensitive details rather than publishing them in an ordinary issue.
No monitored mailbox, response deadline, or private-reporting setting is claimed.

The release workflows use read-only repository permissions. They do not publish
packages, create tags, select licenses, or change repository visibility. Retained
historical logs are evidence about prior checks, not secrets or authorization data.
Human privacy and distribution review remain necessary before public launch.
