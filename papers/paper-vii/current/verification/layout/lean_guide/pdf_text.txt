1 Reading a Paper VII Lean theorem
1.1 Three readings of one construction
The traditional reading begins with a finite state space, its operator algebra and a packet resolu-
tion. It derives matrix identities and explains what they mean for dynamics and recovery. The
visual reading displays the same objects as corners, address sets, syndrome subspaces and local
coordinates. The Lean reading asks a further question: what precise data must be supplied before
each conclusion can be constructed?
An endpoint is a theorem whose conclusion expresses the desired result. A supporting lemma
may isolate one algebraic or analytic step. A definition constructs an object but is not itself a proof
that the object has every advertised property. The formalization deliberately uses several layers:
general ring identities, complex matrix specializations, norm estimates, real calculus, spectral con-
structions and manifold calculus. Reading only a final theorem name loses the distinction between
these layers.
The source base is the unchanged v0.6.0 snapshot. Older supplements explain how coverage grew,
but their partial descriptions are not the last word on the current source. For example, the fourth
block constructed recovery for already orthogonal syndrome data; the fifth block added the spec-
tral reduction and necessity proof for general positive Gram data. The sixth block constructed the
range atlas and global manifold curvature. This guide follows the current declarations and retains
the older history only where it explains an assumption or correction.
1.2 Finite types, matrix types and type classes
Lean’s Matrix d m ℂmeans a function with a row index in d, a column index in m, and values in
the complex numbers. The indices are types, not necessarily integers. A Fintype d instance gives
the finite enumeration needed for a sum or dimension; a DecidableEq d instance lets a definition
decide whether two indices agree. Fin n is the type of integers smaller than the natural number n.
It supplies a concrete index type without replacing an arbitrary finite type throughout the library.
The notation Type* leaves a universe level implicit. Braces in a binder, such as \{n : Type*\},
denote an implicit argument inferred from later data. Round parentheses denote an explicit argu-
ment. Square brackets denote a type-class argument: a structure or property that instance search
should obtain. These brackets do not make an assumption disappear. A theorem with [Nonemp
ty n] is only available when the state index has an inhabitant. A theorem with [Invertible D]
has an actual invertibility requirement even though no ordinary parameter named hD is printed.
The declarations set autoImplicit false. Consequently an undeclared symbol is not silently
promoted to a fresh theorem variable. A local variable command can still supply variables and
type classes to subsequent declarations. An excerpt must therefore be read together with its sur-
rounding section, not as an independent file. The chapter contracts explain those surrounding
assumptions; the source file and line register permit a direct check.

1.3 Quantifiers and the information a structure stores
A family P : I →R is one element of the ring for each packet index.
A dependent family
P : (i : F) →J i →Matrix (D i) (D i) ℂallows both the local dimension and the local packet-
address type to vary with the tensor factor. This is more general than a tensor power of one fixed
matrix.
The packet structure stores pairwise multiplication and completeness. Its multiplication law in-
cludes the diagonal case, so idempotence is a consequence. It does not store self-adjointness; that
is supplied only in the star-ring layer. This distinction lets circuit reconstruction work over any
ring while the unitary identities require an adjoint.

Read proj : I →R as the object, mul_proj as its orthogonality law and sum_proj as its complete
resolution of the identity. In a matrix realization the first law is 𝑃𝑖𝑃𝑗= 𝛿𝑖𝑗𝑃𝑖. The second is
∑𝑖𝑃𝑖= 1. No commutative multiplication assumption is present: matrix multiplication remains
operator composition.
Structures used later have a different role. OrthogonalSyndromes stores an already normalized
orthogonal error family, and KnillLaflamme.Data stores a general positive Gram matrix. Data.dia
gonal constructs diagonal error data; its active positive directions are then normalized to construct
OrthogonalSyndromes. The existence of the general Gram data is an assumption of sufficiency;
necessity constructs such data from an actual recovery. The final equivalence joins both directions.
The correct reading keeps these roles separate rather than interpreting every structure field as a
fact proved from scratch.
1.4 How to read a proof script
The scripts repeatedly use a small set of proof moves. rw replaces an expression using a stated
equality. simp only performs a controlled reduction with an explicit list of lemmas; simp also uses
the available simplification database. ext i j reduces a matrix equality to equality of each entry.
funext proves equality of functions by comparing values. constructor starts the two obligations

of a conjunction or equivalence. rintro decomposes quantified and existential data. obtain names
an existential witness already proved to exist. refine fixes the overall shape of a term and leaves
specified holes to prove.
The tactic noncomm_ring normalizes ring expressions without commuting factors. It is appropriate
for identities involving 𝑃𝑏𝑈𝑃𝑎. Ordinary ring is used for scalar arithmetic or commutative coef-
ficient expressions. Reading a ring-normalization step as permission to reorder arbitrary matrix
factors would give an incorrect mathematical proof.
A line beginning have proves or names a local intermediate assertion. The goal remains the same
until that assertion is used. A calc block presents a chain of equalities or inequalities; each link is
a separate obligation. Induction on a list proves all finite circuit depths, including the empty list.
A finite example verified by norm_num or fin_cases proves that concrete example, not a general-
dimensional theorem.
For a derivative identity the important move is often HasDerivAt.unique: two proven derivatives of
the same function at a point must coincide. The script first differentiates a product, then rewrites
the product as a constant or as a known function, then invokes uniqueness. Thus the differentiated
projector and unitary identities are derived from actual functions and their derivatives, rather than
postulated as unrelated first-order data.
1.5 Scope is a part of the theorem
The finite-sector results have broad mathematical strength, but several tempting extensions lie out-
side their conclusions. A statement about the span of an algebra orbit permits every matrix in that
algebra; it does not say a physically specified unitary gate set reaches every vector. A finite chan-
nel complete-positivity theorem quantifies over every finite reference index; it does not formalize
arbitrary infinite reference Hilbert spaces. A derivative computation under supplied smoothness
does not prove the existence of a Schrödinger solution for every initial condition.
The projected-connection modules do use arbitrary smooth real parameter manifolds and com-
plete normed model spaces, which is broader than a single finite-dimensional chart. This mathe-
matical parameter-space generality is distinct from the paper’s unproved continuum physics con-
jectures. Neither the word “manifold” nor an abstract C-star-algebra estimate supplies a contin-
uum tower, a physical constraint algebra, a renormalized limit or a Lorentzian emergence theorem.
The guide’s audit follows the proof-audit discipline: type each conclusion under its actual hy-
potheses and retain its exact source locator. Its self-review follows conservative mathematical
proofreading: source statements and proofs remain untouched. Source identity and code-excerpt
fidelity are fresh documentation checks. Saved compiler and axiom transcripts are inherited proof
evidence. This distinction continues through the replay chapter and full result map.

3.1 One seed: identify the actual image before counting it
The starting coefficient array is 𝐶∈Mat𝑑×𝑚(ℂ). Left multiplication by an arbitrary 𝑑× 𝑑matrix
changes each row independently within the row space of 𝐶. This observation is the entire mech-
anism behind the orbit dimension formula. Lean first defines the row space as the range of the
actual right-multiplication linear map; it then defines the orbit as the range of that map acting on
all 𝑑rows. It does not assume an orbit dimension as an input.
Contract. The row and multiplicity index types d and m have finite enumerations. The orbit is an
algebra-action orbit {𝐴𝐶∶𝐴∈Mat𝑑×𝑑(ℂ)}, already a linear subspace. Its dimension result has no
nonempty-row assumption. The full-orbit equivalence adds [Nonempty d] because it cancels the
positive row cardinality.
The lemma mem_orbit_iff_rows supplies both directions. If 𝑋= 𝐴𝐶, each row of 𝑋is a linear
combination of rows of 𝐶. Conversely, choose one coefficient row for each row of 𝑋, collect them
into a matrix 𝐴, and obtain 𝐴𝐶= 𝑋. The latter choice is an existence argument using classical
choice. It is not a numerical algorithm for choosing coefficients.
The explicit linear equivalence below packages that row-by-row correspondence. Its domain is the
subspace of reachable coefficient arrays; its codomain is the function space whose value at each
row is a member of the row space. Both inverse laws reduce to the underlying functions.
