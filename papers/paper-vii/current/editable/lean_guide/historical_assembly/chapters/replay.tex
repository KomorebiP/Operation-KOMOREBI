\subsection{Rebuild only this guide}
The delivered guide directory contains the complete TeX, generated navigation, rendered code and raw excerpts needed for its PDF. \code{build.py} resolves its paths relative to itself and stages all inputs in a temporary build directory. It performs four complete XeLaTeX passes and copies the finished PDF and diagnostics back. It does not require the original source tree, regenerate mathematical evidence or invoke Lean.

\begin{Verbatim}[fontsize=\small,breaklines=true,breakanywhere=true]
python editable/lean_guide/build.py
\end{Verbatim}

Run this from the final package root, or give an absolute path to the script. The environment needs Python 3, XeLaTeX, the specified fonts and TeX packages. For documentation regeneration, \code{assemble.py} also needs FontTools and the unchanged source snapshot. A different source location can be supplied explicitly:

\begin{Verbatim}[fontsize=\small,breaklines=true,breakanywhere=true]
python editable/lean_guide/assemble.py \
  --source source/complete/Paper_VII_Complete_v0.6.0_With_Visual_Appendix/original_snapshot
python editable/lean_guide/build.py
python editable/lean_guide/verify_pdf.py
\end{Verbatim}

Assembly stops if the source counts, inventory, saved axiom reports, hashes or excerpt locations disagree. It is a documentation reconciliation command, not a proof checker. For a new source edition its fixed count expectations and endpoint selection must be deliberately revised, and that revision must be accompanied by the new evidence rather than silently inheriting the old report.

\subsection{Replay the formal development with the pinned kit}
Once the separately supplied pinned portable kit is available, run the preserved verifier with the working directory set to \code{source/complete/Paper_VII_Complete_v0.6.0_With_Visual_Appendix/original_snapshot}, relative to the final package root. Choose a new output directory so the inherited evidence remains reviewable.

\begin{Verbatim}[fontsize=\small,breaklines=true,breakanywhere=true]
python scripts/verify.py --kit /path/to/kit \
  --out verification/my_run --timeout 240
python scripts/audit_constructions.py --kit /path/to/kit \
  --run verification/my_run
python scripts/test_verifier.py
\end{Verbatim}

The verifier checks the runtime version and Mathlib revision before compiling. It builds local modules in dependency order with one worker and strict warnings, compares emitted axiom audits with the exact inventory, and checks both deliberate invalid controls. The construction audit uses the fresh run's actual build interfaces. It rejects stale source or interface identities.

On a host with short execution windows, the preserved checkpoint mechanism can pause after a few fresh checks:

\begin{Verbatim}[fontsize=\small,breaklines=true,breakanywhere=true]
python scripts/verify.py --kit /path/to/kit \
  --out verification/my_run --timeout 240 \
  --max-checks 3 --resume
\end{Verbatim}

Repeat that command until the verifier reports complete success. Exit code 2 means paused or incomplete, not a successful complete proof check. Resume verifies hashes of the verifier, runner, inventory, source dependencies and both public and private compiled interfaces before trusting a cached module. An interrupted build should be treated as incomplete even if some earlier modules passed.

The \code{check_low_memory.py} launcher configures ordinary Lean with a single worker; its name does not promise an enforced memory cap. The formal snapshot is not an ordinary delivered Lake project with a current \code{lakefile}. The provenance manifest supplies the locked portable-kit dependencies. A bare \code{lake build} in this directory would not reproduce the documented verification procedure.
