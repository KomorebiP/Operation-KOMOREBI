# Licensing options

No license has been chosen automatically. Not pursuing patent protection does
not itself grant copyright permissions.

## Common publication choices

### Dual license by material type

- Python, shell, and build code: MIT or BSD-3-Clause
- Manuscript and figures: CC BY 4.0
- Machine-readable result tables: CC0 1.0 or CC BY 4.0

This is often the clearest arrangement for a mathematical research repository.
Each directory should then carry an explicit license notice, and the top-level
README should state the split.

### One permissive software license for everything

Possible, but a software license can be awkward for prose and figures.

### All rights reserved

This is the current interim state. Public viewing is allowed by GitHub's terms,
but no general reuse permission is granted by the repository author.

## Activation steps

1. Choose the license or license split.
2. Replace the top-level `LICENSE` file.
3. Add directory-level notices if different material types use different
   licenses.
4. Add the selected SPDX identifiers to `CITATION.cff` and any archival
   metadata.
5. Re-run the release checklist.
