# Recovery gate development record

This block was reconstructed after workspace maintenance removed unpersisted chart files. The 17 baseline modules were restored from the saved perturbation release and compiled in its original inventory order. Their individual successful bootstrap logs are in this directory. The runtime kit remained available. Bootstrap compiled files are not release evidence and are excluded from the archive.

The final gate is `scripts/verify_polynomial_charts.py`, run against a new `/dev/shm/paper9_charts_recovered_04/build` directory. It reuses only the pinned portable Lean/Mathlib runtime, compiles all project dependencies afresh with warnings as errors and a 240-second per-file cap, checks frozen source hashes before and after the run, prints the axiom dependency closure of every explicit theorem/definition/abbreviation, and rejects any axiom outside `propext`, `Classical.choice`, `Quot.sound`.

A parser defect in the inherited tooling was repaired before the new gate. The old declaration scanner did not include apostrophes in Lean identifiers, and the old printed-axiom parser stopped at the first apostrophe. Both now retain full identifiers. `scripts/check_source_audit.py` verifies distinct `name`, `name'`, and `name''` declarations and axiom reports, and rejection of duplicates, mismatches, and forbidden axioms. The parser regression is itself a gate. This fix does not retrospectively change the preserved earlier release evidence.

All three new expanded contract files compiled on their first development attempt. They expose actual polynomial derivatives, actual `eval₂`, explicit residue-ball/root subtypes, and the actual coordinate projection, rather than assuming a suitable minor or solution function.

The new positive control uses `F(X,T)=X²−T` at the origin and prime two. Its full Jacobian is surjective, its prescribed solved-X block is zero, and the nearby parameter `T=2` has no root, already modulo four. Development attempt 01 failed because the `toZModPow` import was missing. Attempts 02–04 failed in numeral normalization under that ring homomorphism. Attempt 05 passed after writing two as one plus one and checking the final equality in `ZMod 4`. These were import/normalization failures, not mathematical counterexamples to the intended control. All failed logs are retained.

The four negative controls deliberately fail elaboration: global root uniqueness, rectangular uniqueness, an extra digit of perturbation precision, and a prescribed coordinate split despite a singular solved block. The corresponding positive control theorems certify the mathematical obstruction; a negative-control compiler error by itself would not establish one.

The first fresh gate, `replay_recovered_01`, was interrupted by filesystem exhaustion after 14 mathematical modules passed. Python could not write its final JSON report, leaving the file empty. Existing logs and a `DISK_EXHAUSTION_FAILURE.json` record were retained. The interrupted compiled build was discarded after recording its file hashes. Once disk space was available, the unchanged frozen sources were started again in the wholly fresh `replay_recovered_02` directory. Only that second run can supply completed verification evidence.

The second fresh gate, `replay_recovered_02`, was also interrupted by filesystem exhaustion, after all 25 mathematical modules, both positive control modules, and two contract modules passed. Its existing logs and failure record were retained; the discarded reproducible compiled build is recorded by file hashes. Neither interrupted run is presented as a completed pass.

The third run, `/dev/shm/paper9_charts_recovered_03`, wrote a complete FAILED report. It failed before compiling any project source because the pinned kit launcher could not create its temporary compatibility-adapter directory under the full `/tmp` filesystem.

The fourth run uses a fresh `/dev/shm/paper9_charts_recovered_04` build and output directory. The existing unchanged compatibility adapter shipped in the pinned kit is preloaded from its original path, so the launcher does not need to copy it to `/tmp`. `TMPDIR=/dev/shm` places the runner’s empty temporary directory on the memory filesystem. Both settings are supported by the existing launcher and runner. No compiler, runtime, verifier, runner, or mathematical source was changed for this environment repair. `execution_environment.json` records the exact adapter hash and the two safe environment overrides. Final verification status is reported solely by the completed fourth-run JSON report.
