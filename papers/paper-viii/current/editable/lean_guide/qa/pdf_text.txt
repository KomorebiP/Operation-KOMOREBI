1 Reading a finite formal development
1.1 The objects precede the theorem names
A packet representation starts with a finite projector family and an operator. A structured represen-
tation adds explicit factor matrices or tensor coordinates. A compiler starts with a finite candidate
tree and an independently defined set of legal cuts. An error theorem starts with actual errors in a
normed space and budgets that bound them. In each case, the theorem follows the object being mod-
eled. Reading only the endpoint name misses the domain, norm, convention, and supplied data on
which its conclusion depends.
Use the traditional paper’s original item numbers to find the corresponding subsection in Section 12.
Then locate its declaration in Section 13 and its module in Section 14. For a first reading, work through
the chapters in order. The small-core chapter is longer because the final block proves optimality from
several independent ingredients, rather than accepting an optimality certificate as input.
1.2 A short Lean vocabulary

Meaning in this guide

A function with row type m, column type n, and coefficients in
K. Finite index instances provide finite sums; rectangular shapes

A finite enumeration of the index type. Empty index types are
allowed unless a nonempty hypothesis is separately stated.
[DecidableEq I]
Equality can be decided where the construction needs it. It is not
a numerical tolerance test.

Natural indices smaller than 𝑘. The type Fin 0 is empty.

The matrix or algebra element has a two-sided multiplicative in-

Either some v, a finite candidate value, or none, an unreachable /

surrounding its declaration.

1.3 How to read a proof
rw rewrites by an equality. simp applies named simplification facts; simp only restricts that collection.
funext reduces equality of functions to equality at an arbitrary argument, while ext exposes entries of
a structured object. refine supplies a proof expression with remaining holes. have names an interme-
diate proposition and its proof. exact closes a goal with a term of the required type.
Induction is visible in the recursive structured algorithms and dynamic programs. A calc chain shows
the successive equalities or inequalities used in a norm estimate. Arithmetic tactics have limited roles:
ring normalizes polynomial identities, omega handles integer and natural-number constraints, and
linarith/nlinarith combine supplied real inequalities. They do not supply unrecorded analytic or
hardware assumptions.

3 Exact packet semantics
3.1 The reused projector family
The unchanged QuantumPacketCore foundation uses a ring R and finite packet type I. The projectors
multiply orthogonally and sum to one. Their block 𝑃𝑏𝐴𝑃𝑎uses the target index first. This algebraic
model already covers noncommutative operator multiplication.
Source: formalization/QuantumPacketCore.lean.
Exact lines 22–25. Excerpt packet_family. SHA-256 in Section 15.
structure PacketFamily (R I : Type*) [Ring R] [Fintype I] [DecidableEq I] where
proj : I →R
mul_proj : ∀i j, proj i * proj j = if i = j then proj i else 0
sum_proj : ∑i, proj i = 1
Proof reading. The structure fields are assumptions defining a packet family. Idempotence is derived
by setting the two indices equal; reconstruction follows by expanding the two sums of projectors. A
finite projector family is supplied to later theorems, so discovery of an appropriate family is a separate
mathematical or application task.
3.2 Deleting exact zero blocks
activeBlocks P A filters the finite set of ordered packet pairs by the predicate that the actual block is
unequal to zero. evalActive sums only those surviving blocks.
Source: formalization/PacketIR.lean.
Exact lines 41–49. Excerpt active_evaluation. SHA-256 in Section 15.
theorem exact_active_evaluation (A : R) : evalActive P A = A := by
classical
have term (e : I × I) :
(if P.block A e.1 e.2 ≠0 then P.block A e.1 e.2 else 0) =
P.block A e.1 e.2 := by

Proof reading. The local lemma term checks two cases: a block equals zero or it does not. In either case,

theorem product_support_inclusion (A B : R) (b a : I)
(h : P.block (A * B) b a ≠0) :
∃c, P.block A b c ≠0 ∧P.block B c a ≠0 := by
classical
by_contra no

intro c _

· simp [hc]

Proof reading. The premise says the product block is nonzero. Assume no intermediate packet has

3.5 The Python prototype is a different object
The historical Python prototype’s support accessor returns stored block keys, which may include ex-
plicitly stored zeros. The formal activeBlocks set instead tests exact nonzero matrix blocks. The two
objects agree only when the stored representation has already removed all zero blocks and realizes
the same matrices. No automatic equivalence between the prototype and the Lean representation is
asserted here.

4 Representation algebra and declared cost models
4.1 Why a count theorem can have a short proof
PacketCostModels defines finite address and event types before counting them. The block widths are
natural numbers; a diagonal block has a pair of within-block indices. A thin factor has one ambient
and one rank index. An application event additionally has a right-hand-side index and a Boolean
distinguishing multiplication from accumulation. The Boolean gives the declared two-scalar-operation
convention.
Source: formalization/PacketCostModels.lean.
Exact lines 68–73. Excerpt bdlr_count. SHA-256 in Section 15.
theorem bdlr_application_count {I : Type*} [Fintype I]
(width : I →ℕ) (n r q : ℕ) :
Fintype.card (BDLROperation I width n r q) =
2 * q * ((∑i, width i ^ 2) + 2 * n * r) := by
simp [BDLROperation, pow_two]
ring
Proof reading. The type BDLROperation is a sum of the diagonal-action, right-factor, and left-factor
event types. simp evaluates cardinalities of finite products and sums; ring rearranges the resulting
polynomial. The count includes the accumulation into the diagonal result through the declared third
kernel. It does not establish how many GPU instructions run.
The storage count concerns stored scalar values; sparse index metadata and workspace are outside the
corresponding models. The materialization theorem counts an explicit dense low-rank multiplication
followed by one addition per output entry. Its quadratic remainder is exactly 𝑛2. This is a count for
that declared construction, rather than a lower bound for every conceivable implementation.
