The gate rejects unsafe declarations, project axioms, opaque declarations, and any collected axiom
outside propext, Classical.choice, and Quot.sound. It also checks the exact namespace and
theorem-kind counts. These expected counts are version-specific: a legitimate addition requires
revisiting them, not deleting the checks to make the build pass.
The source-policy check additionally rejects proof placeholders and specified shortcuts. Text scan-
ning alone cannot establish a theorem’s correctness. It is one gate among the build, compiled map
checks, axiom traversal, and source-integrity checks.
7.3 Reading the inherited transcript
The saved transcript has 143 named records. Some say that the target depends on no axioms.
Others list a subset of the allowed standard basis. The final line records 468 audited namespace
declarations, including 229 theoremInfo entries, and 143 explicit mapped targets.
The difference between 88 and 229 is not a discrepancy. Eighty-eight counts the theorem dec-
larations deliberately mapped to the paper. The compiled namespace count includes generated
theorems and other supporting theorem entries. Similarly, 143 and 468 refer to different denomi-
nators: mapped human-facing targets versus every compiled entry under the audited namespace.
This guide checked that the transcript’s named records agree with the map and the audit directives.
It also checked the transcript hash against the inherited report. That establishes consistency and
byte identity of the preserved materials. It does not authenticate an external compiler session by
itself. A new execution is the direct way to regenerate compiler evidence from those sources.

7.5 Replay from a preserved source copy
The source release offers an offline integrity mode. From its root, run:

This mode checks release membership, checksums, map and audit consistency, manuscript status
references, and the saved transcript. It does not run Lean. It is suitable for checking that a copied
release still matches its own preserved manifest.
