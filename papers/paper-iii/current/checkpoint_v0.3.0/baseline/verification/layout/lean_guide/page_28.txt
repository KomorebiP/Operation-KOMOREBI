7.1 The pinned environment is part of the claim
The formal project names Lean leanprover/lean4:v4.34.0-rc2, with reported Lean commit 6a10
ac8c22beadecabdbb0919c2b50214762f91d. Its Lake manifest pins Mathlib at aeb72f1e9981b6d35b
426b16dca7759be3e7ba06. The project version is 1.0.1. Warnings are promoted to errors through
moreLeanArgs = ["-E", "warning"].
The preserved release deliberately omits compiled outputs and dependency caches. A fresh en-
vironment therefore needs the pinned toolchain and the dependencies named by the manifest.
Rebuilding the PDF guide does not need Lean. Replaying the mathematical formalization does.
Descriptive dependency branches such as master or main are not substitutes for exact manifest
revisions. Updating a dependency and obtaining a successful build may be useful, but it is a new
verification event. The original event remains tied to the recorded environment.
7.2 A map gate and a namespace gate answer different questions
The authoritative scripts/verify_theorem_map.py checks the map row sequence, uniqueness,
compiled declaration kinds, manuscript status annotations, inherited references, and explicit au-
dit coverage. In the pinned compiled environment, it distinguishes the 88 theorem targets from
the 55 construction targets. A lexical scan can locate these declarations in source, but does not
independently elaborate their types.
The kernel-audit file asks Lean to print transitive axioms for all mapped targets. It then inspects the
compiled Komorebi.PaperIII namespace, including generated declarations and implementation
auxiliaries. This second step protects the boundary beyond just the manually listed names.
