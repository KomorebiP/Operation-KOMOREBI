# Reproduce Paper III release 1.0.0

Use a separate working copy. The shipped manifest describes the frozen package, and rebuilding changes generated records and output bytes.

## Integrity and PDF structure

Python 3.11 or newer is sufficient for:

```bash
python3 VERIFY_RELEASE.py
```

With PyMuPDF installed, `python3 VERIFY_RELEASE.py --pdf` also parses each current PDF and checks internal destination pages. An optional `--output` receipt must be outside the frozen tree.

## Mathematical computation

The current run used Python 3.12.14, SymPy 1.14.0 and mpmath 1.3.0. The higher-order scripts use exact rational and polynomial arithmetic. From the release root:

```bash
python3 checkpoint_v0.3.0/tools/exact_packet_checks.py --output /absolute/path/to/section16.json
python3 checkpoint_v0.3.0/tests/section17/exact_section17.py --output /absolute/path/to/section17.json
python3 tests/test_higher_packet_calculus.py
python3 guides/visual/checks/verify_examples.py
python3 tests/verify_inherited_formal_evidence.py
```

The last three commands write their documented receipts in the working copy. They do not execute Lean. The expected main assertion totals are 15,331, 2,622 and 677; the separate figure suite has 124 checks and four rejected false controls. `evidence/review/computation_review.md` describes the exact ranges, repeated assertions and limits. Do not reinterpret sampled norm bounds as exact norm computations.

## Lean

Follow `formal/README_CONTINUATION.md`. It gives the official exact compiler archive, verified digest, portable dependency restore helper and all four final verification phases. The nine package commits are pinned in `formal/lake-manifest.json`. The cold phase refuses an existing owned object directory. Each new label names a new immutable log directory. The final accepted phase receipts and source/object hashes are in `formal/verification/FINAL_VERIFICATION_SUMMARY.json`.

The distribution includes owned generated objects as evidence and convenience, but a reproducible verification starts from a new empty owned object directory. The compiler distribution, dependency checkouts, Git histories and large upstream cache files are not bundled.

## Reading PDFs

The build requires XeLaTeX, pdfLaTeX and BibTeX with the packages imported by the supplied TeX sources. It also uses Python 3.11+, PyMuPDF and ReportLab. The observed environment is recorded in `TYPESETTING_ENVIRONMENT.json`.

Install these font families through the normal font manager: P052, Nimbus Sans, Latin Modern Mono, Latin Modern Math and DejaVu Sans Mono. These are the same families used by the retained monograph styles. Font binaries are not redistributed in the package.

Run:

```bash
python3 BUILD_PDFS.py --build-dir /absolute/path/to/paper3-build
```

The builder compiles the active authored manuscript first. It uses its actual TeX auxiliary labels for the Lean-guide locator table and the statement register. It then compiles the visual and Lean guides, compiles the analytic supplement, and assembles the complete reader. Source prose, figures, formal proof files and historical evidence are not regenerated by this command. It sets `SOURCE_DATE_EPOCH` to the release date and retains final build logs. Exact PDF bytes can still depend on TeX, fonts and library versions.

Inspect the rendered outputs after building. The released edition's visual QA covers every page of each distinct component, with full-size inspection of covers, dense proof pages, diagrams and Lean displays. The combined reader is also checked for component order, internal destinations, outlines and page labels.

## Editing the mathematical source

The active paper is `manuscript/Paper_III_Traditional_Final.tex`, which includes four files under `manuscript/chapters/`. The active visual atlas is `manuscript/visual_atlas.tex`. The visual companion uses `guides/visual/source/pages_final.tex`. The current Lean scope chapter is `guides/lean/chapters/00_current_release.tex`; its later map chapters describe the preserved finite baseline explicitly.

The checkpoint's old assembly scripts regenerate historical source. They are historical tools and are not the current manuscript editor. Use `BUILD_PDFS.py` for the active edition. The statement register records active environment/proof hashes separately from historical raw-source hashes and previous locators.
