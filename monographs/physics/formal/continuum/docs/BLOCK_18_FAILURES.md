# Block 18 development failures and repairs

These are development and execution failures. None is counted as proof evidence. The final checked status, if any, comes only from `verification/final/report.json` and the fresh-extraction rerun.

1. **Copied development tree initially lacked usable local object files.** Imports from the inherited cumulative library failed until the previously checked Block 17 build cache was copied into the Block 18 working tree for development. The production verifier does not trust that copy: it deletes `.lake/build` and recompiles every active local mathematical module.
2. **Shell derivative generalization initially elaborated the wrong factors.** An early attempt to use a generic iterated-product derivative allowed Lean to infer unsuitable functions. The proof was rewritten with explicit scaled-cosine derivative lemmas and explicit factors before the sixth-order Taylor theorem was accepted.
3. **Taylor normalization/API mismatches.** Development attempts hit `Real.sqrt`/`sq_sqrt` namespace mismatches and expression-normalization failures while rewriting the Taylor polynomial and Big-O remainder. The final proof computes the relevant derivatives explicitly, uses the actual Taylor remainder theorem, and then proves the source quartic-coefficient identity separately.
4. **Momentum-derivative combinator mismatch.** A draft of the group-velocity proof using a real `HasDerivAt.mul_const` route triggered incompatible inferred scalar/module instances. The final proof constructs the derivative of `q * ε` by the product rule, then applies cosine differentiation and exact expression changes. The accepted theorem differentiates the original shell and principal-frequency functions.
5. **Exact arccos derivative algebra required explicit nonzero obligations.** Initial simplification left divisions by `ε` and the square-root denominator unresolved. The final proof derives strict shell-interior bounds, proves the principal sine/square-root identity and denominator positivity, and only then simplifies the derivative coefficient.
6. **Example module had four ordinary proof failures.** The first draft omitted the topology scope for `𝓝`, used a simplifier that did not normalize the radical correction equality, used a positivity tactic on a negative goal, and left an associative subtraction mismatch in the squared-shell witness. Each was repaired with explicit scope, exact sign reasoning, and calc/ring normalization. The resulting module compiles with warnings as errors.
7. **A direct aggregate development compile failed after source-only module checks.** Running Lean on the individual source files without `-o` checked the files but did not create the `.olean` files required by the aggregate import. Development compilation was switched to explicit object output; the production verifier independently rebuilds all objects in dependency order.
8. **One background verifier launch returned a container transport timeout.** The verifier process itself continued running and wrote its ordinary progress log. A transport timeout is not counted as a pass; only the completed report is eligible as evidence.

No failed attempt was converted into an admission, custom axiom, disabled kernel check, or weakened false-control contract.
