# Block 12 development failures and repairs

The completed production report, not development attempts, determines the release status. At documentation time there are **15 failed and 8 successful single-module development compilations** with preserved snapshots and receipts. One initial failure was an import/staging error before the needed baseline object had become available. The remaining failures were proof elaboration/API/interface issues. None is counted as a checked theorem.

Repairs used explicit finite Pythagoras, bounded-map construction, typed HasSum/Tendsto interfaces, actual closed-graph membership, explicit namespace/domain parameters, transparent coordinate equalities and exact rational/complex arithmetic. No admissions or custom axioms were introduced. A missing eigenvalue namespace caused cascaded metavariables and a deterministic heartbeat limit in one example attempt; it was repaired by the correct namespace and explicit normalization, not by changing the statement to a vacuous one.

A separate API-name probe reported unavailable names; its source is retained as `verification/development/block12/CounterAPI_probe.lean`, outside the active mathematical inventory. The six new deliberately false controls were previewed in a separate batch; all six produced their intended unsolved-goal diagnostic, with no import or syntax errors. Those expected rejections are not failed positive proofs.

The full 977-theorem baseline passed in `verification/block11_baseline/report.json`. The final cumulative production run is recorded separately in `verification/final/report.json`; any full-run failure must be retained and reported before a repaired final pass. Runtime restoration is logged under the baseline evidence and was checksum-verified.
