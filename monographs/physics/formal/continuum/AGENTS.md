# Proof development rules

Read `CONTINUE_HERE.md`, `docs/SOURCE_MAP.md`, and the latest proof guide before editing. Preserve all v0.40 predecessor mathematical modules byte-for-byte unless a separately documented migration is required. Every new claim must be tied to an exact source statement or clearly labeled as formal support.

Keep active proofs free of admissions, custom axioms, unsafe/native evaluation, and kernel-bypass options. Treat every proof-bearing definition as part of the API audit. Keep deliberately invalid tests isolated in `negative_controls`. Never count a timeout, interrupted run, numerical test, cached object, status poll, or prose status as a checked theorem.

Use the pinned toolchain and dependencies. Preserve failed attempts and diagnostics. Update the inventory, source map, verification receipts, continuation file, preservation ledger, and checksums together. Do not describe a transported finite-resolution Euclidean subspace as the ordinary dyadic-box subspace until that identification is formally proved.
