8 Reproduction, audit, and evidence handling
8.1 The exact environment
The cyclic analytic formalization’s toolchain file specifies leanprover/lean4:v4.34.0-rc2. The recorded
compiler commit is 6a10ac8c22beadecabdbb0919c2b50214762f91d. Mathlib is pinned at aeb72f1e9981
b6d35b426b16dca7759be3e7ba06. The complete revision table for the nine packages is printed in the
dependency appendix and preserved in lake-manifest.json.
The project has autoImplicit = false and relaxedAutoImplicit = false. The verified replay es-
tablishes warning rejection through the explicit control in Section 9, which distinguishes the inherited
setting from the corrected invocation. The aggregate import integrates the development, while the ex-
plicit kernel audit checks the mapped declarations and the namespace. Build caches are excluded from
the release source.
8.2 What the saved kernel transcript establishes
The saved transcript contains one axiom record for each of the 1,164 mapped targets and ends with
the namespace audit’s pass line. The guide generator compares the target sets in four places: the theo-
rem map, the declaration-kind contract, the audit source’s explicit directives, and the transcript. It also
checks that every recorded axiom belongs to the permitted set of three axioms.
This reconciliation proves consistency of the preserved evidence files with the preserved source
identities. It does not repeat elaboration, type checking, or a live environment traversal. The names-
pace totals of 2,234 declarations and 1,999 theorem declarations are inherited results, not counts newly
obtained from a running Lean process. A lexical source parser cannot substitute for elaborated decla-
ration types or compiler-generated declarations.
8.3 Static reconciliation
The generator validates every one of the 119 Lean source files against the canonical SHA-256 manifest. It
resolves the 1,164 target names to source declarations and checks the theorem-versus-construction split
against the explicit contract. It emits the complete row catalog, 68-result ledger, direct-import inventory,
exact pins, and source-excerpt manifest.
The source policy scan excludes comments and string literals before checking for forbidden proof
placeholders and unsafe shortcuts. The kernel-audit file is treated separately because its exclusion logic
necessarily names prohibited axioms. This is a source-hygiene check. It does not establish that elabora-
tion succeeds.
The 43 declarations in SemanticChecks.lean are supported by their source and preserved execution
evidence. Static reconciliation does not relabel them as newly executed tests. The separate verification
chapter records the production replay and compiler controls. The 119 mathematical source files re-
mained unchanged.

8.4 Replay the original release gate
Use a disposable copy of the canonical PRSC_IV directory with the pinned Lean toolchain and depen-
dencies available. The documented release gate requires Lean and checksums, including a full compiler
replay.
bash VERIFY.sh --release
If the original release archive is available, its exact checks of archive entries can be included:
bash VERIFY.sh --release --archive /path/to/PRSC_IV_v1.0.0.zip
Use the exact formal source archive for checks of archive entries. The collected book is a different artifact
and does not have that archive’s entry set.
The gate also accepts a validated external dependency cache:
bash VERIFY.sh --release --lean-packages-cache /path/to/packages
The cache must match the pinned package revisions. The release checker requires a clean project with-
out a preexisting local build cache. It creates and cleans its local attachment under its own rules. A
fresh extracted copy is the clearest way to avoid mixing source verification with prior build state.
For a focused manual inspection from formalization/lean, the relevant commands include:
lake --wfail build
lake env lean -E warning KomorebiPaperIV/KernelAudit.lean
These commands describe the inherited manual gate. For the verified warning policy and full pro-
duction replay, use the procedure in the next chapter. The full release gate additionally checks exact
kinds and manuscript associations, source policy, document reconstruction, checksums, and archive
properties when requested.
8.5 Failure modes worth recognizing
A dependency revision mismatch means the attempted replay is not the pinned release environment.
A saved transcript whose target set differs from the contract is incomplete evidence even if its final line
says pass. A declaration that is present lexically but fails to elaborate has not passed a new formal run.
A PDF that builds successfully says nothing by itself about the Lean proofs.
The inherited computational audit also reports that an older strengthened numerical suite accepted
mutations to a projector identity and a zero-counting constant. Its reported pass totals therefore cannot
certify theorems. The canonical formal contract and kernel evidence should not be replaced by those
historical totals from finite tests. Finite checks can still detect selected regressions, but their sensitivity
and scope must be stated.

9.2 Controls and their diagnostics
A valid projector-idempotence application is accepted. An explicit false theorem, an admitted proof,
an omitted premise, an injected custom axiom, and a definition presented as a theorem must produce
their intended rejection diagnostics. A timeout, signal kill, missing import, or unrelated API error does
not count as successful rejection.
The warning policy is material to this contract. The inherited -E warning setting accepted an isolated
deliberately admitted proof with exit code 0. The verified replay instead uses -DwarningAsError=true,
which rejected that fixture with exit code 1. The production mathematical sources were not weakened
or edited.
The verifier tests use the recovered typed source contract and adversarial mutations of rows, targets,
evidence labels, axiom reports, and process outcomes. A descendant-process cleanup fixture waits for
explicit child readiness before applying a separate bounded execution deadline. An earlier timeout

9.5 Mathematical boundaries
Imported standard fact 11.1 remains outside the 68-result contract. The core does not assert universal
simplicity of all zeros, positivity of every reduced zero, a full displacement expansion, or a zeta func-
tional equation. Eventual simplicity, branch choices, multiplicities, and nearest-pole asymptotics retain
their stated hypotheses and ranges. The separately preserved visual reader includes a branch-sensitive
clarification of reciprocal powers. No older editable source is substituted for that reader.
