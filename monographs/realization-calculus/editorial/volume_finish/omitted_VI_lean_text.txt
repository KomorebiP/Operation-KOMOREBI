11.4 Commands on an already provisioned system
Use a disposable copy of the original snapshot when reproducing the original verifier: it writes new
reports beside its input. Do not overwrite the preserved historical evidence. On a system that already
has the declared toolchain, pinned dependencies, and documented Python packages, run from that
copy:
python3 verification/verify.py
This is the full original gate, including Python tests, verifier controls, the Lean build, dependency revi-
sion and cleanliness checks, and the namespace axiom audit. The --static-only option still dispatches
Python tests and controls. It is not a guarantee of a dependency-free run. The current edition’s portable
verification scripts separately document the available subset used here.
To inspect the production theorem namespace in an already provisioned Lean checkout, the original
underlying commands are:
lake build KomorebiPaperVI
lake env lean -DwarningAsError=true KernelAudit.lean
Running those commands successfully against a different toolchain or different dependency revision
would create a new evidence revision. Preserve its logs and provenance rather than relabeling the in-
herited record.
