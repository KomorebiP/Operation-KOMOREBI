2.2 Record identity and source provenance
Each current record has a stable ID, kind, title, statement text, optional proof text, source locator, hashes,
formal status, declaration targets, and a scope note. These fields identify the actual current statement
and the proof text that accompanies it. The preserved executable payload additionally supplies its own
dependency annotations, semantic profiles, evidence coordinates, and fingerprints for its versioned
source.
There are 28 definitions, 28 theorems, 22 corollaries, 16 propositions, three lemmas, three classical
inputs, seven boundaries, and one remark. The 69 theorem/proposition/corollary/lemma records
have attached proof bodies. Definitions and boundary statements are not counted as proved theorems
merely because they occupy records.
A fingerprint in the preserved runtime provides a content identity under that payload’s generating
convention. It is not a proof certificate. The release gate checks the source digest, ID count, graph,
AST coverage, selected API behavior, and exact fixtures. It does not establish all mathematical content
through independent formal reconstruction.
2.3 Statement AST and typed signatures
The preserved runtime statement AST has one entry per stable ID in its versioned source. The statuses
are 20 TYPED_CORE, 81 STRUCTURED_SYMBOLIC, and seven TEXTUAL_SEMANTIC. A typed-core record
points to a signature declaring parameters, requirements where supplied, and a return description.
The AST segments statements into prose and mathematical surfaces. Some expressions are recognized
as relations or direct-sum expressions. Others retain latex_expr leaves. Even a typed-core record can
contain these leaves. Consequently, “typed core” refers to the attached interface signature, not to a
complete formal elaboration or a proof term.
The signature for block intertwining describes a logical equivalence between the global and local
equations. Its source proof remains attached separately. The runtime can evaluate a finite instance.
These are three different representations with three different evidentiary roles.

3 Evidence semantics and certification scope
3.1 Independent evidence coordinates
The preserved runtime evidence object separates source, KIR, Python, and Lean. Its source coordinate
identifies that payload’s source, and its KIR coordinate records validation of that version. Python
evidence reports exact finite fixtures for 26 records. Its Lean coordinate points to eight historical source
mappings.
The catalogue uses the formal correspondence map instead. Each of the 108 records carries a status
and scope note, and each proof-level statement has its own correspondence assessment. The verification
index distinguishes the execution evidence attached to each component.
No coordinate upgrades another automatically. Exact arithmetic removes floating-point ambiguity
from a finite computation. It does not quantify over arbitrary fields, modules, dimensions, or topological
spaces. A mapped Lean declaration proves its own formal statement under its dependencies. Its relation
to the source statement must still be read from the mapping.

3.5 What PASS means
A release-gate pass means the named package checks succeeded. A fixture pass means a concrete exact
computation satisfied its assertion. A transport-gate pass means all operation flags that this runtime
checked were accepted. None of these strings, taken alone, means that the entire 108-record foundation
has been formally proved by the runtime.
The full source proof catalog is included so that a reader can inspect mathematical arguments beyond
the runtime. Editorial reproduction of those arguments is not an adversarial proof audit or a new
formal verification claim.
4 Executable action contracts
4.1 Input and output conventions
The API is a Python command that emits JSON on successful calls. Exact arithmetic actions use SymPy
matrices. Integers and rational strings such as "3/7" preserve rational values. JSON floating-point
numbers should be avoided when the intended claim is an exact rational identity. Returned scalar
entries are strings.
