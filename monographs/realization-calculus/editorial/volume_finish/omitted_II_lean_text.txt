C Source excerpts and reproduction inventory
Every printed Lean listing comes from an exact UTF-8 excerpt in excerpts/*.lean.txt. The adjacent
*.render.txt file escapes TeX control characters and substitutes a math font glyph where the code font
lacks one. It preserves token order. Exact source text, not the display fallback, is the object to copy into
an editor. Excerpts retain their surrounding source context only when that context is printed. They are
not standalone Lean files. generated/excerpts.json records each source path, inclusive source line
range, the SHA-256 digests of each full source file, exact excerpt, and display file. generated/theore
m_map.json contains all 25 rows with fully qualified targets, classifications, scopes, boundaries, and
lexical source locations. generated/mapped_source_index.json provides an alphabetical target index.
generated/static_identity_audit.json records all manifest comparisons and the optional baseline
comparison performed for this edition.
build_guide_data.py uses only the Python standard library. It generates the map, import table,
pins, excerpts, and current static audit without invoking Lean. build_guide.sh calls that generator and
runs XeLaTeX four times. The monograph build uses system-installed P052, Nimbus Sans, DejaVu Sans
Mono, and Latin Modern Math fonts with recorded dependency hashes. The required LaTeX packages
are listed in the preamble. The independent PDF check script uses PyMuPDF and Pillow for page
rendering and contact sheets.
The foundational source remains preserved. The broader constructions live in formal/current/
and are indexed by the chapter-wide correspondence. Editing this guide cannot by itself repair or
strengthen a Lean theorem. A mathematical change to the formal component requires a separate source
change, a new compile, an updated map when appropriate, and new execution evidence.
