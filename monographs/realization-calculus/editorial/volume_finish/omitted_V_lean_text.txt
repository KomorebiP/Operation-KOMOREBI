8.3 Reproduce from a working copy
Use a writable copy of the original release to run its verification entry points, because they write status
and log files beside the sources. Keep the packaged original snapshot unchanged as the provenance
reference. The following commands start in that copied release root, which contains VERIFY_PAPER.py,
formalization, companion, and verification.
The retained commands below describe the September formal release entry points. They do not
reproduce the missing October 5 available-checks runner. The original formal-release pipeline expects
the pinned Lean toolchain, its pinned dependencies, the Python requirements in companion/requiremen
ts.txt, pypdf, pdfLaTeX, and Poppler tools. Once those prerequisites are available, obtain the mathlib
cache in the Lean project:
cd formalization/lean
lake exe cache get
cd ../..
python3 VERIFY_PAPER.py
This full entry point checks the reviewed source hashes, calls the Lean verifier, runs the original com-
panion tests, repeats the optimized static checks, replays numerical experiments, regenerates figure
pairs, and rebuilds the selected 39-page source manuscript. It reproduces the original integrated formal-
core release, not the later combined two-part traditional PDF.
For the formal source and exact-model subset, use:
python3 verification/verify.py
This command checks the actual toolchain version, builds the local Lean library, checks pinned de-
pendency revisions and tracked-file cleanliness, and runs KernelAudit.lean with warnings treated as

8.4 Manual inspection of the formal build
To inspect the principal operations separately, work inside formalization/lean:
lake env lean --version
lake build KomorebiPaperV
lake env lean -DwarningAsError=true KernelAudit.lean
A successful build without the audit is incomplete evidence for the release’s declared axiom policy. A
successful audit of changed sources is a new result that should be recorded with new source hashes.
Do not reuse an old transcript as though it described a modified source tree.
The historical audit’s final success line is:
PAPER_V_CANDIDATE_TARGET_AUDIT_PASS: 225 theorem targets; 827 namespace declarations
The whole transcript, compiler version, source pins, and exit status matter. Searching for this line in a
file is provenance reconciliation, not a substitute for executing the audit.
8.5 The historical runtime adapter
The original environment used a narrow executable self-location adapter. Its ordinary process-specific
executable path returned a permission error, while /proc/self/exe was accessible. The source adapter
redirected only the current process’s own executable-link query. The bundled documentation records
that the distributed compiler and kernel were unchanged.
The retained positive control accepted a valid arithmetic theorem and the negative control rejected
an invalid proof with exit code one. These are useful runtime controls, but the full source build and
namespace audit remain the decisive historical evidence. The adapter is environment-specific and un-
necessary on a normal installation. Toolchain binaries and compiled dependency caches are not in-
cluded in this package.
