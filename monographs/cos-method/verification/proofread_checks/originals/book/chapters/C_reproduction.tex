\section{Replayed numerical controls}\label{app:fresh-validation}
The numerical replay evaluates the six retained regression groups on the
supplied engine without modifying the engine source. It also runs two
independent containment controls. The machine-readable replay record states
the actual environment, commands, source hashes, test counts, and outcomes.
Those records are separate from the retained timing tables in the main text.

A successful finite replay is evidence about those executions. It is not a
proof of all inputs or of the arithmetic library. Directed enclosures rely on
the stated interval arithmetic and transcendental implementation. The shared
interval-precision context requires sequential calls. Floating summary fields
are display values. The outward decimal endpoint strings carry the numerical
enclosure.

\section{Why parsing and output are part of the proof obligation}
An interval can be valid internally and become invalid when printed. A narrow
logarithmic width can also disappear if it is first evaluated in an
insufficient point-precision context. The implementation therefore preserves
literal interval endpoints, compares an upper bound on the multiplicative
ratio with a lower bound on the requested tolerance, and serializes the lower
and upper endpoints outward. Unsupported domain inputs are rejected rather
than admitted to a formula outside its hypotheses.

\section{Figure and data provenance}\label{app:provenance}
The empirical figures use the retained numerical tables. The visual atlas
uses declared finite models and its own reproducible Python generators.
These are distinct sources of evidence. A diagram of an exact identity is
not a new runtime benchmark, and a replacement layout is not a new numerical
experiment.

Three empirical illustrations need a particular qualification. The raw
singular-value vectors for the phase-rank and QR illustrations and the raw
eigenvalue vector behind one packet schematic were not retained. Their
published replacements use the exact recorded rank audit, the recorded QR
discrepancy audit, and the available rounded packet-center and second-moment
labels with the formal packet definitions. No missing samples are inferred.
The corresponding limitation remains visible in each figure caption.

\section{Rebuilding and replaying}
Run the document builder from the package root:
\begin{lstlisting}
python build.py
\end{lstlisting}
It compiles the editable LaTeX source and writes the monograph PDF. A TeX
installation with the packages listed in the source is required.

Run the numerical replay separately:
\begin{lstlisting}
python replay.py --include-controls
\end{lstlisting}
The replay writes new logs rather than overwriting retained results. The
pinned Lean project and its reproduction instructions reside in the
\path{lean/} directory. Compiler and dependency caches are not bundled.
Reproduction requires the exact pinned toolchain and dependencies, or their
reconstruction. The guide distinguishes that requirement from the retained
compiler evidence.

\section{Scope of the publication checks}
The assembly audit checks that every theorem, lemma, proposition, corollary,
and remark from the primary mathematical source is retained. It checks
labels, references, source mappings, and the compiled page geometry. The
Python controls are rerun separately. No new Lean kernel check or native-GPU
benchmark is claimed. The complete record is supplied with the editable
sources.
