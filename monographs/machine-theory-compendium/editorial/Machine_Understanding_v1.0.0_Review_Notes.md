## Mathematical boundaries tightened

### Task-dependent interpreter information is charged

The new counting proposition uses a fixed interpreter and fixed-length program/artifact fields. Any task-specific information placed into the program counts toward the joint capacity bound. A task-independent installed decoder remains declared background rather than being charged anew for each message. This does not prove a runtime lower bound for an individual problem or certify minimal source-code length. The all-Boolean-functions example is a worst-case family statement, not a claim that every Boolean function requires a truth table.

### A designed code and an installed decoder are different contracts

The earlier graph theorem allows a decoder to be designed for the code. The new result freezes each recipient's procedure and instruction/memory bounds first. A candidate artifact is valid only if every recipient returns the required output within those limits. For each sender observation, one artifact must lie in the intersection of all still-possible cases' acceptable sets. Nonempty individual acceptable sets are not sufficient when their intersection is empty.

The minimum codebook is a finite covering problem. Counting codebook entries does not automatically compress their physical representations. An index code requires a corresponding installed and charged index decoder. A counterexample separates a graph lower bound of one from an installed-codebook minimum of two. Another failure mode is insufficient sender information, which cannot be repaired merely by making the recipient faster.

### One tree must satisfy all resource budgets

The state includes every variable relevant to transitions, backgrounds, permissions, costs and targets. Experiments must be admissible throughout the current support and change the state before the next decision. The finite horizon is a mathematical scope limit, not an unreported execution timeout.

Online costs are nonnegative integer vectors with separate named units. Controller storage counts every record in the explicit installed tree, including mutually exclusive branches. A shared directed acyclic graph or arbitrary program is a different representation. Fixed interpreter tables and model descriptions are additional installed costs, not zero-cost discoveries.

The recurrence is exact for the declared charges. When those charges conservatively bound a physical implementation, feasibility supplies a sufficient physical budget rather than its exact optimum. Pareto pruning preserves simultaneous budget feasibility because both the online maximum and the stored-record sum are monotone in child profiles. The theorem does not claim efficient global synthesis or a shortest general program.

### Separate optima cannot be assembled into a fictitious witness

The four-origin example uses equality tests, not threshold comparisons. A direct reveal gives profile (4 online units, 5 controller records). The equality chain gives (3, 7). Their separate minima cannot produce (3, 5). The reference code enumerates the exact nondominated frontier and independently checks the policies. This is a strict tradeoff rather than a dominated comparison presented as a frontier.

### The instrument charges the same actual recipient procedures

One exact J diagnostic returns its post-operation display. The sender subtracts its old display to obtain c and broadcasts one three-bit field. Recipient A has old (a,b), recipient B old (s,b). Their frozen programs each perform one modular addition and return the appropriate post-J coordinates. No report or controller address is silently transmitted in addition to the message. Unused binary patterns are rejected rather than assigned hidden meanings.

The six-record literal controller applies to one known old-record fibre. It is not a claim that one six-record tree handles every private initial observation without dispatch information. The generic arithmetic demonstration handles all 25 fibres and records its source bytes separately. Modular operations, physical calls and bits are different coordinates, not added into a unitless total. Assignments and dispatch are not counted as modular arithmetic. The primitive ledger describes the specified procedure, not a universal lower bound on processors.

The earlier noisy results remain conditional Bayesian statements. Three noisy reports do not provide an exact state certificate merely because they produce a high posterior. The exact and noisy contracts are not conflated in the final synthesis.

## Exact implementation review

`resource_contracts.py` validates finite model tables, dimensions, nonnegative costs, transitions, observation ids and admissibility. Its optimizer returns a nondominated profile with an explicit policy or an empty finite frontier. Its checker does not invoke that optimizer: it validates every reachable branch, then independently simulates every permitted initial state and counts all compiled records. Invalid recipient outputs, unavailable operations, missing or extra branches, and horizon overruns are rejected.

`edition_checks.py` compares codebook optimization against direct encoder enumeration and resource optimization against a separately written full observation-history tree enumeration. It covers every ordered pair of the declared two-state experiment tables, every binary terminal-validity table, every nonempty support, and horizons zero through two. The four-origin tradeoff is checked separately. All 125 instrument states and every H/W/J word through length four are checked against both recipients' coordinate updates. Negative tests exercise malformed models and invalid witnesses.

These alternative algorithms are authored within the same project. They are useful cross-checks, not independent external validation. Domain and per-group counts are in `validation/final/edition_checks.json`. The mathematical arguments, not the volume of finite assertions, support general statements.

The legacy schema v1 is retained with additional input pinning. Its verifier is project-authored, not an independently authenticated plugin distribution. No Git revision, external attestation, separate memory cap, affinity cap, or proof-kernel run is claimed.
