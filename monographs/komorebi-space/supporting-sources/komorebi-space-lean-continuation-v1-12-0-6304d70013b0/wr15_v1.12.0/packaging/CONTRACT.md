# v1.12.0 release-builder contract

`package_release.py` is an authored candidate pending independent script review. Preparation has not built or saved a release. No package acceptance is claimed by the bounded tests.

The standard-library builder defaults to the recovered parent archive `recovery/Komorebi_Space_Lean_Continuation_v1.11.0.zip` and its expanded tree under `recovery/v1.11.0/`. The parent ZIP must have SHA-256 `40a5ddecb526dcb1f60c4475e3648f2b5aa906d2b4b5070f4a8b1c59db4d83d1`. All 5,862 manifest payloads and the manifest itself, 5,863 total files, must match the expanded parent. It preserves every parent file unchanged under `inherited_v1.11.0/`.

The default current run is `wr15_v1.12.0/integration/runs/clean_wr15_01`; `--run` supports a later genuinely accepted attempt. The default final type audit is `reviews/WR15_MATH_AUDIT.md`. Source, assembly inventory, overlay, reviewed helpers, reviewed validator, command logs, full new types, cumulative declarations, runtime snapshot, and terminal receipts must match their accepted hashes. Counts come from actual source/declaration inventories and the accepted receipt. No theorem count is guessed.

The release ledger must say `status: ACCEPTED`, bind `formal_receipt_sha256` and `postflight_sha256`, and record `review_verdicts` exactly as `{"mathematics":"PASS","verifier":"PASS","packaging_script":"PASS"}`. Its `acceptance_evidence_sha256` map must bind the final mathematical review, `reviews/VERIFIER_REVIEW.md`, `reviews/reviewed_helpers.json`, `reviews/PACKAGING_SCRIPT_REVIEW.md`, `formal/tests/control_manifest.json`, all reviewed `integration/scripts/` helpers, `integration/postflight/validate.py`, and the chosen run's `receipt.json`, `postflight.json`, `axioms.json`, `new_declarations.json`, `declarations_sorted.json`, and `runtime_snapshot.json`.

The mathematical review must contain exact receipt, postflight, cumulative axiom report, full new-declaration report, and each new production-source hash. The verifier review must contain exact receipt, postflight, and reviewed-helper manifest hashes. The packaging-script review must contain this exact script's SHA-256. The builder binds supplied final review verdicts; it does not itself establish the mathematical validity of a prose audit.

All six root documents must exist: `README.md`, `PROGRESS_LEDGER.md`, `PROGRESS_LEDGER.json`, `VERIFICATION_SUMMARY.json`, `FORMAL_COVERAGE.json`, and `NEXT_RESEARCH_BLOCK.md`. Current project sources, controls, successful and failed attempts, evidence, and reviews are retained under `wr15_v1.12.0/`. Current `build`, Python cache, Git/cache, runtime and download directories plus compiled-object suffixes are excluded. Historical parent provenance and PDFs remain unchanged. No new PDF is accepted in this Lean-only continuation.

The output directory must already exist, and none of the four release destinations may exist. The builder creates an expanded release, `Komorebi_Space_Lean_Continuation_v1.12.0.zip`, `Komorebi_Space_Lean_Progress_v1.12.0.md`, and `Komorebi_Space_Lean_Delivery_Verification_v1.12.0.json`. It copies the accepted run's entire source snapshot to top-level `formal/`, copies the six root documents, writes a complete SHA-256 payload manifest, checks safe unique paths and all ZIP payload CRCs/hashes, and compares ZIP, expanded release, inherited parent, and current formal source. Input identities and acceptance are checked again before delivery. It never modifies accepted input files and refuses all overwrites. A failed build may leave incomplete new destinations and will not silently resume or overwrite them.

`--parent-only` validates parent identity without requiring current acceptance. `--check-only` validates all parent and acceptance gates without writing a release. Running without either flag builds only after those gates pass. The root reviewer owns final builder acceptance; an independent artifact check remains a separate gate after actual creation.
