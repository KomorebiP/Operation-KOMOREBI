# Development incidents — v0.4.0

These are failed or diagnostic development attempts, not accepted verification results. All proof compilation logs are retained under `verification/development/v0.4.0` with unique filenames and adjacent command metadata. Not every intermediate source text was snapshotted, so the logs are not presented as a complete executable history of every edit.

1. The container rejected an interactive execution request with `StreamingExecNotEnabledContainerError`. Ordinary calls and locally polled subprocesses were used instead. An initial restore launch referenced a script that had not been created after that rejected request; it was restarted correctly. The successful restoration verified the concatenated five-part archive hash before extracting the pinned kit.
2. A source-excerpt helper searched for a nonexisting LaTeX heading and raised `ValueError`. Reading from the actual theorem label recovered the intended text. The publication and proof sources were unaffected.
3. An early Lean draft used the reserved token lambda as an identifier. Renaming the coefficient binder fixed the parser rejection.
4. Scalar conversions required explicit `nsmul_eq_mul` normalization and the existing `ZMod.natCast_zmod_val` fact. Other drafts required explicit type and admissibility arguments because selector groups and rational preimages carry inherited instances. The final theorem hypotheses were not weakened.
5. Some attempted rewrites did not match the elaborated coercion expressions. Proofs were repaired with typed equations, congruence, subtype extensionality and explicit `change` commands. Warnings promoted to errors, including unused simplifiers and unnecessary simplification, were corrected rather than disabled.
6. The pinned Mathlib does not expose several tested additive completion-functor/lift API names. The probe and its failure log are retained outside accepted tests. The actual continuous extension was constructed through the existing canonical comparison equivalences, then its canonical-point equation, uniqueness, composition and coordinate action were proved. No missing API or assumed map was substituted silently.
7. A root-entrypoint rebuild attempted while a new dependency had failed saw a missing compiled module. The dependency and root subsequently compiled. The final verifier deletes all project compiled output and rebuilds serially, so no stale or missing dependency result is counted as accepted evidence.
8. New test drafts needed explicit natural multipliers, admissibility proof arguments, and direct injectivity/surjectivity reasoning. They were corrected before the full run. A prior draft's error-recovery messages mentioning admitted declarations were not accepted; the final axiom audit rejects any transitive dependency on `sorryAx`.
9. The six deliberately invalid new controls fail by design. Each has an independently proved positive contract or counterexample, an exact required diagnostic, a nonzero compiler exit, and no timeout in the accepted run. Missing imports and process startup failures are not valid negative-test evidence.

10. The documentation index validator found eight inherited entries whose line offsets pointed to the blank line before the declaration. It now locates the exact theorem-name token, verifies all 260 names/types against the exported environment, and retains the old index in history. This change affects source navigation, not proof content.

No printed theorem required a correction in this tranche. The complete monograph remains unchanged. The accepted clean rebuild, declaration audit, contracts, controls, same-kernel replay and endpoint checks are recorded separately in `verification/accepted_v0.4.0/run.json`.
