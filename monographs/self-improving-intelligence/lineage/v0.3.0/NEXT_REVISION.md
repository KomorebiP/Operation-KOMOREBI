# Next revision: improve how discovery rules are acquired

Version 0.3 synthesizes an internal compiler decision from a fixed primitive grammar. It also makes a representational obstruction explicit: missing remaining-depth information prevents any function of the old features from selecting the right decision. The missing feature is exposed from a supplied registry. This is more than selecting a complete named compiler template, but it is not autonomous construction of its own semantics or improvement of its grammar enumerator.

## Highest-value next step

Develop a costed procedure that proposes and evaluates useful search features or rule languages from prior compiler traces, then compare its ability to synthesize new discovery rules from fresh common starting conditions. Charge unsuccessful languages, teacher construction, model access, verification, installed information, and the accepted rule. A faster enumerator on an unchanged lookup table must not be mistaken for generalization across new semantics.

## Focused theoretical directions

1. **Repair-relative pruning.** The cover-number bound now exposes why singleton counts fail when one repair covers several cases. A useful next certificate would bound cover requirements incrementally without hiding an expensive exact cover computation inside the heuristic.
2. **Generated rules beyond one canonical proof gate.** Extend a restricted arithmetic proof language with explicit checked derivations. Keep the learning procedure distinct from the trusted proof checker and do not infer universal validity from finitely many training prefixes.
3. **Transferable acquisition of compiler heuristics.** Use prior synthesized rules to order later searches, and compare both search quality and total development cost on genuinely changed rule families. Keep cold-start comparisons separate from library reuse.
4. **Resources beyond table accesses.** Derive and implement an execution model that charges primitive operations, stored ASTs, model queries and witness checking without declaring every access equivalent to an arbitrary Python instruction.
5. **Uncertain and acquired models.** Connect the fixed-model-tag construction to explicit observations that can reject an inadequate model family. A renamed variable is not an observation and a new repair language changes the pruning premises.

A first edition can consolidate a clear finite scope without settling unrestricted recursive self-improvement. It should explain exactly what is supplied, generated, checked, transferred, and charged, and distinguish a better inner discovery rule from a better method for producing such rules.
