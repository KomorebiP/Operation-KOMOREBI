# Active representation growth: results

Author: **Komorebi P.**  
5 September 2026. CPU experiment with frozen neural weights.

## What changed

The previous workspace could diagnose the tested cubic behavior as unavailable
to its readers. This release can construct executable products of existing
signals, determine which product explains new evidence, retain it in a library,
and install its amplitude as a new editable memory coordinate.

It learned and independently validated nine product expressions from 18
development tasks. Those expressions span the cubic and quartic monomials
generated by applying the supplied product constructor to pairs of existing
signals. They were not separately installed as primitive cubic/quartic solvers.
Their constructor and the search space were supplied.

## Fresh replication after the initial failure

Each task begins with nine observations on x,z in {-1,0,1}. Every accepted
prediction is scored at 32 fresh continuous input pairs with three query readers.
An exact task requires all 96 outputs within 1e-6 of the independent oracle.
The numbers below are task counts, not rounded query accuracy.

| Fresh single-extension tasks | Total new queries | Correct accepted | Wrong accepted | Ambiguous |
|---|---:|---:|---:|---:|
| Original maximum-spread selector | 2 | 50/144 | 0 | 94 |
| Random grid probes | 2 | 78/144 | 0 | 66 |
| Revised prediction-partition selector | 2 | 144/144 | 0 | 0 |
| Revised selector with a reserved fresh validation point | 2 | 144/144 | 0 | 0 |
| Random selection with the same validation allowance | 2 | 109/144 | 0 | 35 |

The revised selector counts potential reductions in parameter uncertainty and
distinguishes groups of hypotheses predicting different outputs. Prediction
magnitude only breaks ties. This avoids rewarding distant corner probes that
produce the same answer under several competing explanations.

| Fresh rules combining two learned signals | Total new queries | Correct accepted | Wrong accepted | Ambiguous |
|---|---:|---:|---:|---:|
| Original maximum-spread selector | 4 | 61/72 | 0 | 11 |
| Revised selector | 4 | 72/72 | 0 | 0 |
| Revised selector with reserved validation | 4 | 72/72 | 0 | 0 |
| Random selection with the same validation allowance | 4 | 60/72 | 0 | 12 |

The new validation point is sampled independently from the continuous input
domain. It counts toward the stated query budget. Both matched validated arms
receive the same validation point for a task. No scoring output is used for
selection or validation.

## Unsupported behavior and false acceptance

The 48 fresh unsupported tasks contain degree-five terms absent from the
available feature compositions.

| Fresh unsupported tasks | Wrong accepted | Incompatible | Ambiguous |
|---|---:|---:|---:|
| Original selector, four-query cap | 14 | 34 | 0 |
| Revised selector, four-query cap | 5 | 43 | 0 |
| Revised selector with reserved validation, four-query cap | 0 | 48 | 0 |
| Random selection with reserved validation, four-query cap | 0 | 47 | 1 |

This is evidence that fresh validation matters in this environment. It is not
a proof that one probe detects every unsupported rule. Any finite set of probes
can leave unseen distinctions, and noise was not studied.

“Identified within search” alone can still be wrong about the world. The
reserved query tests that conditional conclusion rather than treating it as
certainty.

## The initial run is preserved

Before revising the selector, a disjoint earlier task set gave:

| Initial single-extension comparison | Correct accepted |
|---|---:|
| No additional probes | 48/144 |
| Maximum-spread active, two queries | 52/144 |
| Random, two queries | 81/144 |
| Maximum-spread active, four queries | 143/144 |
| Random, four queries | 136/144 |
| Maximum-spread active, eight queries | 144/144 |
| Fixed original grammar, four-query cap | 0/144 |

The first active heuristic therefore failed its tight-budget comparison. On
48 initial unsupported cases it accepted 16 wrong explanations at four queries
and one at eight queries. Even using only one new feature for tasks requiring
two caused one false acceptance out of 72 tasks.

Those failures motivated the revision. We did not overwrite their predictions
or source snapshot. `results/initial_sources` holds the first frozen code.
`results/fresh` uses a new seed, new coefficients and new scoring inputs. It
reuses the same families, so this is a fresh replication after diagnostic
development, not a test on entirely unseen operator families.

## What the library contributes

The library stores nine executable expressions with development provenance and
separate validation observations. Rebuilding it without any test task reproduces
the stored library exactly.

On the initial single-extension set, disabling further expression construction
but retaining the library preserved 143/144 four-query solutions. Removing both
the library and construction yielded no accepted correct solutions.

For initial two-signal combinations, library-only reuse solved 63/72 with four
queries and 72/72 with eight. Reconstructing the same programs from the product
constructor matched 63/72 at four queries. Thus memory transfers executable
capability without rebuilding the expressions, but it does not improve accuracy
over complete resynthesis in this small search. No wall-clock speedup is claimed.

The combinatorial search remains supplied: single-extension arms allow at most
one extra feature, and combination arms allow at most two. The learner does not
yet autonomously select or expand that complexity budget. The number of fitted
candidate representations is saved for every arm.

## Actual expanded workspaces

All 216 successful fresh single and combination cases were installed in the
frozen seed-0 model's expanded workspace. Their actual three-reader outputs
matched the discovered programs with maximum discrepancy **1.39e-13**.

Three imported current-state snapshots retained their states and outputs exactly during growth. The import does not migrate the full earlier histories; the original bank remains included under `baseline/`.
This preservation comes from explicit addressing, immutable program identities,
zero new amplitudes in old workspaces, and unchanged neural weights. It is not
evidence that retraining a shared encoder avoids forgetting.

A cubic workspace accepted seven independent edit constraints: increase f(2,0)
by one and retain six specified values. Its change on fresh inputs matched
(x cubed minus x)/6 across value, difference, and sum readers, with maximum
effect discrepancy **2.40e-14** in the initial bridge audit. Undo and conflicting
edits were also checked.

  and the underlying Python commands were run.

## Limits on the conclusion

The new learning is program selection, fitted signal amplitudes, and persistent
reuse. A small reader adapter is fitted from valid output examples. The old
734 neural parameters are unchanged. Exact symbolic fitting also corrects the
old core's value function during adoption, so the end-to-end accuracy must not
be attributed to the frozen neural induction dynamics.

The constructor, base signals, product equivalences, sparse fitting algorithm,
probe policy, noiseless environment, and acceptance thresholds are supplied.
The new coordinates extend the executable representation but not the neural
encoder. The prototype does not invent new primitive operations.

The tasks remain low-dimensional synthetic polynomial worlds with an oracle
that can answer new probes. No ARC evaluation was performed, and no broad
large algebraic signal model capability is established.
